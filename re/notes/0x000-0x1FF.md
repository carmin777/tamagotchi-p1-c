# ROM 0x000–0x1FF (page 0 "zero page" of subroutines + vectors + ISRs)

Conventions: `M[a]` = RAM nibble (4 bits). `XP:XH:XL` = X pointer (12 bits; **XL/XH form 8 bits and
`ldpx/lbpx/retd` only increment within that 256-nibble page**). Flags: C=1, Z=2, D=4 (decimal), I=8.
`calz n` = call to ROM 0x0n (page 0). Addresses in parentheses = ROM. Evidence: tama.asm (agg23),
cpu.c (ops[]), and traces in `out/range0/` (scripts s.txt, s2.txt, s3.txt; `harness/trace`).
Times measured in the trace: prog-timer tick = **27.34 ms (256/7 Hz ≈ 36.57 Hz)**, free-running (the 1 Hz ISR does not restart the phase); clock-timer = **1 Hz** (M[0x2F] +1 every 1.00 s).

This range contains no game logic: it is the "runtime" (button I/O, time, buzzer, video, utilities). The game
data lives in other pages. Nothing here needs to be emulated in native C beyond what is in "For the rewrite".

## 1. Critical section 0x07D (noise to discard in the rewrite)

### clear_0x07D (0x12–0x1E) / set_f_0x07D (0x09–0x11) / pop_a_x (0x1A–0x1E)
`clear_0x07D`: saves XP,XH,XL,A; `M[0x7D]=0`; `rst f,7` (I=0, disables int). Falls into `pop_a_x` (restores and `ret`).
`set_f_0x07D`: saves likewise; `M[0x7D]=0xF`; `set f,8` (I=1); jumps to `pop_a_x`. Preserves A and X (B and flags may change).
M[0x7D] is a software flag "interrupts allowed" (0 = critical section): if an already-pending ISR enters with
M[0x7D]==0 it returns **without re-enabling** I (see `int_restore_ret`). Called from ~17 sites each
(copy_0x026_7_to_8_9, copy_xhl_to_0x022, clear_0x32_store_yhl, label_31/32, render_asset, 0x206/0x219…).
Pseudo-C: `cli(); ...; sei();`. In single-threaded native C: **eliminate** (the ISR becomes a "call between frames").

## 2. Graphics

### render_asset (0x00–0x08) — "draw_sprite"  (+ stubs 0x1000–0x1023 and sprites 0x1030+)
Draws a ROM sprite into the video buffer. Inputs: `X=XP:XH:XL` = destination (normally XP=1, buffer 0x1xx);
`M[0]=sprite_lo`, `M[1]=sprite_hi`, `M[2]=page` (uses `M[2]&7`). Output: X advanced by 32 nibbles (wrap at 8 bits);
A preserved; B/flags destroyed. Effect: M[0x7D] 0→F (critical section).
Mechanics: `B:A=(M[2]&7)*4`; `pset 0x10; jp gfx_jp_ret_zp (0x1020)`: `call 0x1023 (jpba)` jumps to `0x1000+4*(page)`:
each 4-word stub `ld a,m0; ld b,m1; pset 0x10+page; jpba` jumps to `ROM[0x1000 + page*0x100 + M1*0x10 + M0]`,
where the sprites are 15×`lbpx mx,imm` + `retd imm` (executed in place: they write 32 nibbles to M[X..X+31]). Then
`pset 0; jp set_f_0x07D` (0x1022) returns to the original caller.
**Sprite format**: 32 nibbles = 16 columns × 8 rows (2 nibbles per column: even nibble = rows 0-3, odd = rows 4-7;
bit i of the nibble = row i). "upper half/lower half" in agg23's notes = upper half (rows 0-7) / lower half (rows 8-15).
Sprite id = (page 0–7, idx 0–F) → ROM `0x1000 + 0x100*page + 0x10*idx` (M0 normally 0; M1=idx).
Pseudo-C: `void draw_sprite(u8 *dst /*X*/, int page, int idx){ memcpy(dst, SPRITE[page][idx], 32); }` with data extracted
from the ROM (the pixel data is already a graphics table — see "Useful Addresses.md").
Callers: render_clock_page (0x5FD), misc_render (0x7B7), label_291 (0x961), label_347 (0xDE1).

### Video buffer layout (0x100–0x1FF) and copy_video_buf_to_vram (0x56–0x8C)
Two 32×16 px frames of 128 nibbles each: frame A = {0x100–0x13F (rows 0-7), 0x180–0x1BF (rows 8-15)};
frame B = {0x140–0x17F, 0x1C0–0x1FF}. Nibble of pixel (x,y) relative to the frame base:
`off = 2*x + ((y>>2)&1) + (y>=8 ? 0x80 : 0)`, bit `(y&3)`; 1 = lit pixel.
`copy_video_buf_to_vram`: base = 0x100 + (M[0x2B]<<4 | M[0x2A]) (0x00 = frame A shown, 0x40 = frame B). Copies the 128 nibbles
to the LCD VRAM (E00–E4F = rows 0-7, E80–ECF = rows 8-15; icons at E10-11, E22-27, E38-39, … are **not** touched):
```
x 0..7   : VRAM E00+2x          (rows 8-15: E80+2x)
x 8..15  : VRAM E02+2x          (            E82+2x)      // E12.. for src +0x10
x 16..23 : VRAM E48-2(x-16)     (            EC8-2(x-16))  // mirrored order
x 24..27 : VRAM E36-2(x-24)     (            EB6-...)
x 28..31 : VRAM E2E-2(x-28)     (            EAE-...)
```
(each column = 2 consecutive nibbles; the seg→x mapping comes from tamatool/src/lib/hw.c `seg_pos[]`.) Source offsets copied in order:
+00→E00(16), +80→E80(16), +10→E12(16), +90→E92(16), +20→E48 (5 descending pairs), +2A→E3E(3 pairs), +A0→EC8(5), +AA→EBE(3),
+30→E36(4), +38→E2E(4), +B0→EB6(4), +B8→EAE(4). Side effect: A,B,X,Y,XP,YP destroyed. 12 callers
(0x200,0x27A,0x2AD,0x3EB,0x500,0x594,0x643,0x6A9,0x81E,0x90B,0xAF4,0xE73).
Pseudo-C: `for(y..) for(x..) lcd[y][x] = (buf[base + off(x,y)] >> (y&3)) & 1;` — in the rewrite the framebuffer can be
a plain `bool[16][32]`.

Copy helpers (RAM→RAM, `ldpy mx,my` = M[X]=M[Y],Y++ ; `ldpx a,a` = X++):
- `copy_16_mx_my_ret` (0x8D), `copy_8_mx_my_ret` (0x8F), `copy_3_mx_my_ret` (0x99), `copy_2_mx_my_ret` (0x9B): copy 16/8/3/2 nibbles
  from M[Y..] to M[X..] (return at 0x9E). Callers: copy_video_buf_to_vram; copy_3: 0x61A,0xDE9,0xDEE; copy_2: 0x6F3.
- `copy_10_mx_my_offset_ret` (0x9F), `copy_8_..` (0xA3), `copy_6_..` (0xA7): copy from M[Y..] in **nibble pairs with X
  moving back 2 per pair** (`adc xl,0xC` with C=1 ⇒ XL+=13 mod 16 ≈ −3 after ++ ⇒ pairs at X, X−2, X−4…). Return 0xB2. Only used by copy_video.
  Precondition: C=1 (`set f,1`) and XL≥3 on reaching each `adc`.

### clear_page_0x100 (0x40–0x51) / clear_8_starting_at_a_xp (0x45) / loop_clear_8 (0x47)
`clear_page_0x100`: XP=0; `M[0x2A]=M[0x2B]=0` (shows frame A); clears 0x100–0x1FF (B=0 ⇒ 16 iterations × 16 nibbles; `lbpx` = 2 nibbles).
`clear_8_starting_at_a_xp`: A=page (XP), B=number of 16-nibble blocks (B=0 ⇒ 16), clears `B*16` nibbles of `A:00`. At init (0x246–0x24F) this, together with the rest of `set_init_mem_and_int`, clears 0x000–0x0DF, 0x100–0x26F and the whole LCD (the list in note 0x200 §2.4 was wrong).
clear_page callers: 12 (0x295,0x398,0x3A1,0x3D7,0x53F,0x556,0x631,0x669,0x67E,0x8B9,0x911,0x984); clear_8_starting: set_init_mem_and_int (0x246–0x24F).
Pseudo-C: `memset(&M[0x100],0,256); video_base=0;`

### label_30 (0xCE–0xD3) — select_frame_b (name (?))
XP=0; `M[0x2A]=0, M[0x2B]=4` (frame B shown); returns X=0x03A. The callers then do `lbpx mx,0x40` at 0x3A ⇒ drawing
cursor `M[0x3A]=0,M[0x3B]=4` (=0x140). Pattern "select frame B to draw on". Callers: label_34 (0xDE), 0x297, 0x50A, 0x591, 0xE5E.
label_34 (0xDE–0xE1): same + `jp label_233` (page 7). Callers: 0x642, 0x6A8, 0x818.
M[0x3A],M[0x3B] = current drawing pointer into the buffer (X of render_asset in label_291 (0x95B)) (confirmed by reading 0x95B/0x966).

### label_13 (0x52–0x55) + calz_copy_buf_and_render_misc (0x54) — "present_frame"(?)
`pset 4; call label_145 (0x486)` [animation timers in M[0x5F],M[0x64],M[0x66],M[0x6A] … (?)] and falls into
`pset 4; call copy_buf_and_render_misc (0x400)` and then into `copy_video_buf_to_vram`. Note: `copy_buf_and_render_misc`
(0x400, outside the range) if M[0x4B]==0 fills frame A with 0xF (everything lit) (?), and uses M[0x4A].7 (icon blink) and M[0x48].7 to
call `misc_render`. Callers of label_13: 0x541, 0x985; of 0x54: 0x66D, 0x68B, 0x8F4.

### check_0x04A_highbit (0xB3–0xB6), zero_a_xp_and_bit_high_at_0x048 (0xFB), bit_high_at_0x048 (0xFD)
Test `M[0x4A]&8` / `M[0x48]&8` (`fan mx,8` ⇒ Z=1 if the bit is clear). XP=0 forced (except bit_high_at_0x048, which uses the current XP).
Presentation state bits (M[0x48].7, M[0x4A].7): meaning (?) (0x4A looks like "blinking icon/attention" with a counter in the rest of the nibble:
copy_buf_… does `M[4A]=(M[4A]+1)|8` and uses bit0 as the blink phase). Callers: 0x40C,0x41B,0x596,0x600,0x624,0x710,0x7C3,0xADA,0xD7E / 0x42A,0x602,0x626,0xCBC; 0x598,0x728,0x73C,0xF60,0xF69,0xF85.

## 3. Buttons, delays and input reading

### Input (done in prog_timer_int, 0x16F–0x19F — see §5)
`F40` (K0, active at 0): K00=**R**, K01=**M**, K02=**L** (tamalib `hw.c`). In RAM, active-high: bit0=R, bit1=M, bit2=L.
- `M[0x26]` = buttons pressed now (1=pressed) (bits 0..2 = L,M,R).
- `M[0x27]` = mask of **rising edges** accumulated since the last read (`copy_0x026_7_to_8_9` clears it).
- `M[0x3D]`/`M[0x3E]`/`M[0x3F]` = auto-repeat: `M[0x3D]`=last reading seen; `M[0x3E]` counts ticks with an unchanged reading (4 bits);
  on wrapping around (16 ticks ≈ 436 ms) it becomes 8 and does `M[0x27] |= current & M[0x3F]` (repeats every 8 ticks ≈ 218 ms);
  `M[0x3F]`=mask of buttons with auto-repeat (the time-setting UI uses `0x6` = M and R; 0 turns it off: written at 0x566/0x587).

### copy_0x026_7_to_8_9 (0x21–0x2B) — "read_buttons"
Output: **A = M[0x26] (buttons held), B = M[0x27] (buttons just pressed)**; also writes `M[0x28]=A`, `M[0x29]=B`
(bits: 1=L,2=M,4=R), and clears `M[0x27]` (consumes the edges) inside a critical section. Z/flags undefined.
16 callers (0x1F2,0x201,0x222,0x27B,0x296,0x2C3,0x3A0,0x569,0x56D,0x664,0x66E,0x81F,0x822,0x8B8,0x8F5,0x986).
```
u8 read_buttons(u8 *held,u8 *pressed){ cli(); A=M[0x26]; B=M[0x27]; M[0x27]=0; sei(); M[0x28]=A; M[0x29]=B; }
```
Idiom: `calz copy_0x026_7_to_8_9; fan mx,mask` tests new buttons in M[0x29] (X was left at 0x29); e.g. loop_294 `fan mx,2` waits for M.

### Delays (busy-wait in 27.24 ms ticks)
- `M[0x22]` (lo), `M[0x23]` (hi): 8-bit counter decremented per prog-timer tick; on reaching 0 it stays 0.
- `copy_xhl_to_0x022` (0x2C–0x34): `M[0x22]=XL, M[0x23]=XH` (critical section). 2 callers (0x3C, 0x396).
- `or_0x022_and_0x023` (0x35–0x3B): A = M[0x22] | M[0x23] (Z=1 if the counter is zero). Callers 0x3D, 0x39A.
- `copy_xhl_to_0x022_or_loop_0x023` (0x3C–0x3F) = `delay_ticks(XH:XL)`: loads and waits `while (M[0x22]|M[0x23]);` (no HALT).
  7 callers (0x20,0x394,0x39D,0x645,0x68D,0x6AB,0x90D).
- `store_0x02_into_0x022_3` (0x1F–0x20): `X=2; delay_ticks(2)` and **falls into** `copy_0x026_7_to_8_9` (0x21): "delay 2 ticks (54 ms) and read buttons".
  Caller 0x2B1. (Real name: `wait_2ticks_read_buttons`.)
Pseudo-C: `void delay_ticks(u8 n){ tick22=n; while(tick22) idle(); }` — in native C, 1 tick = 27.24 ms of emulated time.

### label_31 / label_32 / label_33 (0xD4–0xDD) — "any_nibbles_set_2/3"
`clear_0x07D; A=M[Y]; Y++; [label_32: A|=M[Y]; Y++]; A|=M[Y]; set_f_0x07D` ⇒ A = OR of 2 (label_31) or 3 (label_32) nibbles at Y,
Z=1 if all zero (atomic read of multi-nibble counters also written by ISRs). label_31 used at 0xF50,0xF81,0xF8E,0xFA3; label_32 at 0xF2E,0xF77,0xF88,0xFE5.
`label_33` is only the internal label (A|=M[Y]).

## 4. Small utilities

- `zero_a_xp` (0xEF): `A=0; XP=0`. 56 callers. `zero_b_xp` (0xF2): `B=0; XP=0` (14). `one_a_xp` (0xF5): `A=1; XP=1` (17).
- `check_0xX5D_is_1` (0xF8–0xFA): `X=0x5D` (current XP); `cp mx,1`. Z=1 if M[XP:0x5D]==1. Callers 0xC85,0xC96,0xF11,0xF4A,0xF5E,0xFC2,0xFCA.
  M[0x5D] = **species/form** (0=egg, 1=baby…; the stage is M[0x50]) used as an index (0x5D read at 0x92A/0x93B before the jump tables 0xC00/0xD00) (?).
- `springboard_label_238` / `label_38` (0xEC–0xEE): `[A=0]; pset 7; jp label_238 (0x7C0)`. Callers 0x374,0x509,0x983 (label_38) and 0x294,0x527,0x53E,0x555 (springboard).
- `label_35` (0xE2–0xE3) + `label_36` (0xE4–0xEB) + `label_37` (0xEA): **increments two BCD digits "mm" with wrap at 60**:
  label_35: `X=0x12; D=1`. label_36: `M[X]++ (BCD, 4b); X++; M[X]+=carry; if (M[X] >= 6) M[X]=0; D=0`; output **C=1 if there was no wrap**, C=0 if it rolled over to 00.
  Uses: minute tick in the ISR (X comes from `ldpx mx,0` at 0x13F ⇒ X=0x12) and minute adjustment on the time-setting screen (0x573 ⇒ M[0x12..13]).
- `label_67/68/69` (0x1F4–0x1FF): **increments an 8-bit byte in nibbles A(lo),B(hi) with wrap at 24** and stores it in M[X],M[X+1]:
  `a++; b+=carry; if (b==0 || (b==1 && a<8)) store; else {a=0;b=0; store}` (values 0x00–0x17, **binary/hex**, D=0 ⇒ hours 0–23).
  Callers: 0x146 (hour rollover), 0x580 (hour adjustment; B&=1 before). Input: current A,B, X=0x14. Trace s3: M[0x14],M[0x15] go from 0x00…0x17 → 0x00.
- `label_66` (0x1EC–0x1F3): "arm timeout & flush input": `M[0x75]=0; M[0x76]=A; M[0x77]=B; M[0x57]=B; read_buttons();` (XP comes from the caller = 0).
  Callers 0x522 (A=1 or 8, B=0xA/0xC), 0xE5D (A=2). M[0x57]=timeout in seconds (decremented 1/s in the clock ISR); M[0x75..0x77] = screen/state parameters (?).
- `label_282` neighbourhood/0x5A: see RAM.

## 5. Vectors and ISRs

### Vector table (0x100–0x10F)
One `jp` per vector (E0C6S46: 0x100 reset, 0x102 clock timer, 0x104 stopwatch, 0x106 K0x, 0x108 K1x, 0x10A serial, 0x10C prog timer; odd ones never used).
Mapping: 100→reset_vector(0x110), 102→clock_timer_int(0x11D), 10C→prog_timer_int(0x16F), all the others→generic_int(0x116).

### reset_vector (0x110–0x115)
`F=0; SP=0xFF; pset 2; jp reset_vect_cont (0x22A)` (continues outside the range: checks SVD, copies K0→M[0x270], clears RAM, plays sound `Y=0x80`,
if M is pressed at boot → test mode 0x256, otherwise `label_294` waits for M to start — see notes 0x200+).

### generic_int (0x116–0x11C)
Saves F,A,B,XP,XH,XL; `jp int_restore_ret`. (No interrupt other than clock/prog is handled.)

### int_restore_ret (0x15B–0x167) / gen_int_dis_int (0x168–0x16E)
`XP=0; if (M[0x7D]==0) { pop xl,xh,xp,b,a,f; ret /*without set f,8*/ } else { pop…; set f,8; ret }`. (see §1)

### clock_timer_int (0x11D–0x15A) — 1 Hz tick
```
push f,a,b,xp,xh,xl; D=0;
(void)F00;                       // clears the clock int factor
F76=1; F77=0;                    // F76 bit0=WDRST: restarts the watchdog. F77=0: stopwatch (SWRST/SWRUN) stopped — it is not a clock control (datasheet, see "I/O registers used")
F78=1; F79=2;                    // arms the prog timer (run, clock select 2); runs free, the phase is NOT restarted every 1 Hz
F12=1;                           // mask: enables the prog timer int
if (M[0x57]) M[0x57]--;          // timeout in seconds (see label_66)
if (M[0x3C]) {                   // M[0x3C]!=0 => clock running (set)
    D=1; M[0x2E]=1;              // flag "1 s has passed" (consumed by UI/animation)
    M[0x10]++ (BCD); M[0x11]+=carry;           // seconds 00–59
    if (M[0x11] >= 6) {
        M[0x11]=0;
        if (!bcd_inc_minutes_label_36()) {      // minutes M[0x12..13], wrap 60
            hours = M[0x14] | M[0x15]<<4;       // 24h, binary (D=0 after label_36)
            hours = label_67(hours);            // wrap 24
        }
        label_312();                            // pset 0xC; call 0xC7A: per-MINUTE task (touches the needs) (?)
    }
    D=0;
}
// 12-bit counter M[0x2F..0x31]++ every second (always, even without the clock)
if (++M[0x2F]==0 && ++M[0x30]==0 && ++M[0x31]==0) {   // overflow every 4096 s
    if (F70 & 3) { if (check_svd_voltage()) F70 = 0; }   // low battery => leaves the >3.1 V mode
}
goto int_restore_ret;
```
Note: the "TODO: Unused?" comment at 0x142 is wrong: it runs when the minutes roll to 60 (hour increment). Evidence:
trace s3 (hour) and `jp c,label_50` at 0x141 (C=1 = no wrap). Measured seconds: M[0x2F] +1 every 1.00 s (trace o), M[0x10]/M[0x11] only move after M[0x3C]≠0.
`M[0x3C]` is written: 0xF at 0x221 ("hard" boot), 0x58E (confirm the time); 0 at 0x563 (enters the time-setting screen) and 0x1210 (init).

### prog_timer_int (0x16F–0x19F) — 256/7 Hz tick (27.34 ms)
```
push f,a,b,xp,xh,xl; D=0;
configure_buzzer();
(void)F02;                       // clears the factor
b = (~F40) & 7;                  // buttons pressed (1=pressed)
M[0x5A]++;                       // free-running 4-bit counter (entropy/randomness (?))
if (--M[0x22:0x23] underflow) M[0x22]=M[0x23]=0;   // delay_ticks()
a = M[0x26]; M[0x26]=b;
M[0x27] |= (a ^ b) & b;          // rising edges
if (M[0x3D] != b) { M[0x3D]=b; M[0x3E]=0; }
else if (++M[0x3E] == 16/*wrap*/) { M[0x3E]=8; M[0x27] |= b & M[0x3F]; }   // auto-repeat
goto int_restore_ret;
```

### check_svd_voltage (0x1E5–0x1EB) / check_svd_voltage_set_xp_f (0x1E3)
`F73=6; nop5; A=F73; F73=0; A&=8;` ⇒ Z=1 if the battery is OK (>3.1 V), Z=0 if low. `_set_xp_f` first does XP=F. Callers: label_52 (0x157), reset_vect_cont (0x22B).

## 6. Buzzer / sound

### Model
"Tick by tick" sequencer in `configure_buzzer` (0x1A0–0x1C0, called at the start of each prog_timer_int ⇒ step of 27.24 ms). State in RAM (XP=0):
- `M[0x32..0x33]` = **remaining duration** (8 bits; a step lasts value+1 ticks).
- `M[0x34]` = frequency → F74 (bit 3 = 1 ⇒ **silent** step; F74 is only written if bit3=0), `M[0x35]` = envelope → F75.
- `M[0x36..0x37]` = pointer (8 bits) to the next step in the **page E** table (ROM `0xE00+ptr`), incremented by 2 on every fetch; 0x7D = idle.
- `M[0x38..0x39]` = "heavy load protection" timer (reload 0x58); `M[0x58..0x59]` = repeat counter (M[0x59]==0xF ⇒ infinite).
- `M[0x7B]` = **sound on** (0 ⇒ `play_sound` does nothing; toggled by `xor mx,0xF` at 0x54D (menu), initialized to F at 0x120C).

### Step table (0xE7C jpba; 0xE7D…) — format
`jp_table_0xE7D_buzzer` (0xE7C) = `jpba` ⇒ jumps to `0xE00 + (B:A)`. Each entry is code executed in place with `X=0x032`:
`lbpx mx,imm` (writes imm.lo to M[X], imm.hi to M[X+1], X+=2) and ends in `retd imm` (same + returns). Two forms:
- **4 nibbles** (2 words: `lbpx dd; retd ff`): linear step `{dur=dd (lo,hi), freq=ff.lo, env=ff.hi}`; on return XL==6; the pointer (already +2) goes on to the next one.
- **6 nibbles** (3 words: `lbpx dd; lbpx ff; retd pp`): same + new pointer `pp` (jump/loop/end) written to M[0x36..37].
Notable entries: **0x7D** = idle `{dur FF, freq/env 08 (silent), jump 7D}`; 0x80 = long beep (dur 0x30, f=3; played at reset);
0x83–0x90 = descending scale f=7..1, dur 0 each, ending at 0x91 (`00 00 → 7D`); **0x94** = short button beep (dur 1, f=4 → 7D).
(Rest of the table: outside this range, 0xE7D–0xEAD+; data = sound effects — keep as a table of tuples.)

### configure_buzzer (0x1A0–0x1AA, loop_59 0x1AB–0x1C0)
```
void configure_buzzer(void){            // XP=0
  if (dur(M32|M33<<4) != 0) { dur--; if (M[0x34]&8) goto buzzer_off; return; }
  dur--;                                // underflows to 0xFF but will be overwritten
loop:
  p = M[0x36]|M[0x37]<<4; M[0x36..37] = p+2;     // 8 bits
  X=0x32; step_table_E[p]();                     // writes 4 or 6 nibbles starting at M[0x32]
  if (XL==6 || M[0x59]==0xF) goto buzzer_control;          // linear step or infinite repeat
  cnt = M58|M59<<4; cnt--; if (cnt had no borrow) goto buzzer_control;   // jump with repeats left
  M[0x36]=0xD; M[0x37]=0x7;                      // finished: pointer=0x7D
  goto loop;                                     // fetch the idle step
buzzer_control:
  if (M[0x34]&8) goto buzzer_off;
  M[0x38]=8; M[0x39]=5;                          // 0x58: load protection timeout
  F71 |= 1;                                      // heavy load protection ON
  F74 = M[0x34]; F75 = M[0x35];
  F54 &= 7;                                      // turns the buzzer output on (R43)
  return;
buzzer_off:  (0x1D7)
  M[0x38..39]--(8 bits); if (underflow) F71 &= 0xE;   // turns protection off after ~88 silent ticks
  F54 |= 8;                                       // turns the buzzer output off
}
```
In the rewrite: play `play(table)`; frequency = F74 (BZFQ), envelope F75; the output only needs the tones/durations. Called only by prog_timer_int.

### Sound trigger — "play_sound" routines (0xB7–0xCD)
All respect `M[0x7B]` (return doing nothing if 0). Effect (clear_0x32_store_yhl, 0xC2–0xCC, critical section):
`M[0x32]=M[0x33]=0` (forces a fetch on the next tick); `M[0x36]=YL; M[0x37]=YH` (pointer); `M[0x58]=A; M[0x59]=B` (repeat count).
Entry points (XP is forced to 0):
- `if_0x7B_set_clear_0x32_store_0x94_to_0x036_7_set_0x059_to_0xF` (0xBB) = **`play_beep()`**: `Y=0x94`, then falls into 0xBC. 16 callers (buttons/UI: 0x27F,0x2D0,0x2DB,0x2E1,0x3B2,0x3CB,0x508,0x553,0x572,0x579,0x586,0x67D,0x6C5,0x82A,0x833,0x8FE).
- `if_0x7B_set_clear_0x32_store_yhl_set_0x059_to_0xF` (0xBC) = **`play_sound(Y)`**: A=0,B=0xF (infinite loop until the sequence points to 0x7D). 12 callers (0x21B,0x23A (boot, Y=0x80),0x381,0x387,0x38A,0x39F,0x641,0x668,0x6A7,0x6C9,0x6CE,0xAE8).
- `if_0x7B_set_clear_0x32_store_yhl` (0xBF) = generic `play_sound_n(Y, A, B)` (repeat count A|B<<4; B≠F ⇒ finite).
- `xp_0_if_0x7B_set_clear_0x32_store_yhl` (0xB7, B=0, XP=0; and 0xB9 unreachable): `play_sound_n(Y, A, 0)`. Callers 0x31A,0x34D,0xFF1.
Pseudo-C: `void play_sound(u8 ptr){ if(!M[0x7B]) return; dur=0; seq_ptr=ptr; repeat=0xF?; }` (ptr = YL/YH).

### Cycles per instruction — checked against the core manual
Source: *E0C6200/6200A Core CPU Manual* (Epson, 96 pp.; https://download.epson-europe.com/pub/electronics-de/asmic/4bit/60family/62core_e.pdf), table 3.1.1 (instructions by function).
I compared the manual's "Clock" column with the `cycles` field of the `ops[]` table of `harness/tamalib/cpu.c`: of the 76 instructions read automatically, **all match**, except `SLP`, which TamaLIB does not implement (the P1 does not use it). The arithmetic/logic ones (7 cycles, except `INC/DEC` of X/Y/SP and `RRC` with 5) were checked by hand. That is, the reference emulator has the hardware's per-instruction timing: 5 (jumps, `PSET`, `LD`, index ops), 7 (`CALL`, `RET`, flags, arithmetic) and 12 (`RETS`, `RETD`, `LBPX`, `HALT` waking up / interrupt entry).

## 8. For the rewrite (summary)
1. **Discard**: critical section 0x07D, jpba/retd as a mechanism (they become arrays), copy_video in pairs (VRAM mapping), busy-wait delay (becomes the simulator's tick counter).
2. **Keep**: 1 Hz clock (M[0x10..0x15]: BCD sec, BCD min, hour 0–23), 12-bit seconds counter (only affects the battery — irrelevant), 27.24 ms tick
   (buttons, auto-repeat 16/8 ticks, delay, sound), `M[0x57]` timeout, `M[0x2E]` second flag, sound sequencer (page E table).
3. **Interface**: `read_buttons() -> (held,pressed)`; `delay_ticks(n)`; `play_beep()/play_sound(ptr)`; `draw_sprite(buf,page,idx)`; `present()` (32×16 framebuffer + 8 icons).
