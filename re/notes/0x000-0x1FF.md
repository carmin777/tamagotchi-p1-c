# ROM 0x000–0x1FF (página 0 "zero page" de sub-rotinas + vetores + ISRs)

Convenções: `M[a]` = nibble de RAM (4 bits). `XP:XH:XL` = ponteiro X (12 bits; **XL/XH formam 8 bits e
`ldpx/lbpx/retd` só incrementam dentro dessa página de 256 nibbles**). Flags: C=1, Z=2, D=4 (decimal), I=8.
`calz n` = call para ROM 0x0n (página 0). Endereços entre parênteses = ROM. Evidência: tama.asm (agg23),
cpu.c (ops[]), e traces em `out/range0/` (scripts s.txt, s2.txt, s3.txt; `harness/trace`).
Tempos medidos no trace: tick do prog-timer = **27,34 ms (256/7 Hz ≈ 36,57 Hz)**, rodando livre (a ISR de 1 Hz não reinicia a fase); clock-timer = **1 Hz** (M[0x2F] +1 a cada 1,00 s).

Faixa não contém lógica de jogo: é o "runtime" (I/O de botões, tempo, buzzer, vídeo, utilitários). Os dados
de jogo estão em outras páginas. Nada aqui precisa ser emulado em C nativo além do que está em "Para a reescrita".

## 1. Seção crítica 0x07D (ruído a descartar na reescrita)

### clear_0x07D (0x12–0x1E) / set_f_0x07D (0x09–0x11) / pop_a_x (0x1A–0x1E)
`clear_0x07D`: salva XP,XH,XL,A; `M[0x7D]=0`; `rst f,7` (I=0, desabilita int). Cai em `pop_a_x` (restaura e `ret`).
`set_f_0x07D`: salva idem; `M[0x7D]=0xF`; `set f,8` (I=1); salta a `pop_a_x`. Preserva A e X (B e flags podem mudar).
M[0x7D] é uma flag de software "interrupções liberadas" (0 = seção crítica): se uma ISR já pendente entrar com
M[0x7D]==0 ela retorna **sem reabilitar** I (ver `int_restore_ret`). Chamado por ~17 sites cada
(copy_0x026_7_to_8_9, copy_xhl_to_0x022, clear_0x32_store_yhl, label_31/32, render_asset, 0x206/0x219…).
Pseudo-C: `cli(); ...; sei();`. Em C nativo single-thread: **eliminar** (a ISR vira "chamada entre frames").

## 2. Gráficos

### render_asset (0x00–0x08) — "draw_sprite"  (+ stubs 0x1000–0x1023 e sprites 0x1030+)
Desenha um sprite de ROM no buffer de vídeo. Entradas: `X=XP:XH:XL` = destino (normalmente XP=1, buffer 0x1xx);
`M[0]=sprite_lo`, `M[1]=sprite_hi`, `M[2]=página` (usa `M[2]&7`). Saída: X avançado de 32 nibbles (wrap em 8 bits);
A preservado; B/flags destruídos. Efeito: M[0x7D] 0→F (seção crítica).
Mecânica: `B:A=(M[2]&7)*4`; `pset 0x10; jp gfx_jp_ret_zp (0x1020)`: `call 0x1023 (jpba)` salta para `0x1000+4*(page)`:
cada stub de 4 palavras `ld a,m0; ld b,m1; pset 0x10+page; jpba` salta para `ROM[0x1000 + page*0x100 + M1*0x10 + M0]`,
onde os sprites são 15×`lbpx mx,imm` + `retd imm` (executados in-place: gravam 32 nibbles em M[X..X+31]). Depois
`pset 0; jp set_f_0x07D` (0x1022) retorna ao chamador original.
**Formato do sprite**: 32 nibbles = 16 colunas × 8 linhas (2 nibbles por coluna: nibble par = linhas 0-3, ímpar = 4-7;
bit i do nibble = linha i). "upper half/lower half" nas notas do agg23 = metade superior (linhas 0-7) / inferior (8-15).
Id do sprite = (page 0–7, idx 0–F) → ROM `0x1000 + 0x100*page + 0x10*idx` (M0 normalmente 0; M1=idx).
Pseudo-C: `void draw_sprite(u8 *dst /*X*/, int page, int idx){ memcpy(dst, SPRITE[page][idx], 32); }` com dados extraídos
da ROM (os dados de pixel já são tabela de gráficos — ver "Useful Addresses.md").
Chamadores: render_clock_page (0x5FD), misc_render (0x7B7), label_291 (0x961), label_347 (0xDE1).

### Layout do buffer de vídeo (0x100–0x1FF) e copy_video_buf_to_vram (0x56–0x8C)
Dois quadros de 32×16 px em 128 nibbles cada: quadro A = {0x100–0x13F (linhas 0-7), 0x180–0x1BF (linhas 8-15)};
quadro B = {0x140–0x17F, 0x1C0–0x1FF}. Nibble do pixel (x,y) relativo à base do quadro:
`off = 2*x + ((y>>2)&1) + (y>=8 ? 0x80 : 0)`, bit `(y&3)`; 1 = pixel aceso.
`copy_video_buf_to_vram`: base = 0x100 + (M[0x2B]<<4 | M[0x2A]) (0x00 = quadro A mostrado, 0x40 = quadro B). Copia os 128 nibbles
para a VRAM do LCD (E00–E4F = linhas 0-7, E80–ECF = linhas 8-15; ícones em E10-11, E22-27, E38-39, … **não** são tocados):
```
x 0..7   : VRAM E00+2x          (linhas 8-15: E80+2x)
x 8..15  : VRAM E02+2x          (        E82+2x)      // E12.. para src +0x10
x 16..23 : VRAM E48-2(x-16)     (        EC8-2(x-16))  // ordem espelhada
x 24..27 : VRAM E36-2(x-24)     (        EB6-...)
x 28..31 : VRAM E2E-2(x-28)     (        EAE-...)
```
(cada coluna = 2 nibbles consecutivos; mapeamento seg→x vem de tamatool/src/lib/hw.c `seg_pos[]`.) Source offsets copiados na ordem:
+00→E00(16), +80→E80(16), +10→E12(16), +90→E92(16), +20→E48 (5 pares descendentes), +2A→E3E(3 pares), +A0→EC8(5), +AA→EBE(3),
+30→E36(4), +38→E2E(4), +B0→EB6(4), +B8→EAE(4). Efeito colateral: A,B,X,Y,XP,YP destruídos. 12 chamadores
(0x200,0x27A,0x2AD,0x3EB,0x500,0x594,0x643,0x6A9,0x81E,0x90B,0xAF4,0xE73).
Pseudo-C: `for(y..) for(x..) lcd[y][x] = (buf[base + off(x,y)] >> (y&3)) & 1;` — na reescrita o framebuffer pode ser
um `bool[16][32]` direto.

Auxiliares de cópia (RAM→RAM, `ldpy mx,my` = M[X]=M[Y],Y++ ; `ldpx a,a` = X++):
- `copy_16_mx_my_ret` (0x8D), `copy_8_mx_my_ret` (0x8F), `copy_3_mx_my_ret` (0x99), `copy_2_mx_my_ret` (0x9B): copiam 16/8/3/2 nibbles
  de M[Y..] para M[X..] (retornam em 0x9E). Chamadores: copy_video_buf_to_vram; copy_3: 0x61A,0xDE9,0xDEE; copy_2: 0x6F3.
- `copy_10_mx_my_offset_ret` (0x9F), `copy_8_..` (0xA3), `copy_6_..` (0xA7): copiam de M[Y..] em **pares de nibbles com X
  recuando 2 a cada par** (`adc xl,0xC` com C=1 ⇒ XL+=13 mod 16 ≈ −3 após ++ ⇒ pares em X, X−2, X−4…). Retorno 0xB2. Só usados pelo copy_video.
  Pré-condição: C=1 (`set f,1`) e XL≥3 ao chegar em cada `adc`.

### clear_page_0x100 (0x40–0x51) / clear_8_starting_at_a_xp (0x45) / loop_clear_8 (0x47)
`clear_page_0x100`: XP=0; `M[0x2A]=M[0x2B]=0` (mostra quadro A); zera 0x100–0x1FF (B=0 ⇒ 16 iterações × 16 nibbles; `lbpx` = 2 nibbles).
`clear_8_starting_at_a_xp`: A=página (XP), B=nº de blocos de 16 nibbles (B=0 ⇒ 16), zera `B*16` nibbles de `A:00`. No init (0x246–0x24F) isso, somado ao resto de `set_init_mem_and_int`, limpa 0x000–0x0DF, 0x100–0x26F e o LCD inteiro (a lista da nota 0x200 §2.4 estava errada).
Chamadores clear_page: 12 (0x295,0x398,0x3A1,0x3D7,0x53F,0x556,0x631,0x669,0x67E,0x8B9,0x911,0x984); clear_8_starting: set_init_mem_and_int (0x246–0x24F).
Pseudo-C: `memset(&M[0x100],0,256); video_base=0;`

### label_30 (0xCE–0xD3) — select_frame_b (nome (?))
XP=0; `M[0x2A]=0, M[0x2B]=4` (quadro B mostrado); retorna X=0x03A. Os chamadores então fazem `lbpx mx,0x40` em 0x3A ⇒ cursor
de desenho `M[0x3A]=0,M[0x3B]=4` (=0x140). Padrão "selecionar quadro B para desenhar". Chamadores: label_34 (0xDE), 0x297, 0x50A, 0x591, 0xE5E.
label_34 (0xDE–0xE1): idem + `jp label_233` (pág. 7). Chamadores: 0x642, 0x6A8, 0x818.
M[0x3A],M[0x3B] = ponteiro de desenho corrente no buffer (X do render_asset em label_291 (0x95B)) (confirmado por leitura em 0x95B/0x966).

### label_13 (0x52–0x55) + calz_copy_buf_and_render_misc (0x54) — "present_frame"(?)
`pset 4; call label_145 (0x486)` [temporizadores de animação em M[0x5F],M[0x64],M[0x66],M[0x6A] … (?)] e cai em
`pset 4; call copy_buf_and_render_misc (0x400)` e em seguida em `copy_video_buf_to_vram`. Obs.: `copy_buf_and_render_misc`
(0x400, fora da faixa) se M[0x4B]==0 preenche o quadro A com 0xF (tudo aceso) (?), e usa M[0x4A].7 (blink de ícone) e M[0x48].7 para
chamar `misc_render`. Chamadores de label_13: 0x541, 0x985; do 0x54: 0x66D, 0x68B, 0x8F4.

### check_0x04A_highbit (0xB3–0xB6), zero_a_xp_and_bit_high_at_0x048 (0xFB), bit_high_at_0x048 (0xFD)
Testam `M[0x4A]&8` / `M[0x48]&8` (`fan mx,8` ⇒ Z=1 se bit limpo). XP=0 forçado (exceto bit_high_at_0x048 que usa XP corrente).
Bits de estado de apresentação (M[0x48].7, M[0x4A].7): significado (?) (0x4A parece "ícone pisca/atenção" com contador no resto do nibble:
copy_buf_… faz `M[4A]=(M[4A]+1)|8` e usa bit0 como fase de piscar). Chamadores: 0x40C,0x41B,0x596,0x600,0x624,0x710,0x7C3,0xADA,0xD7E / 0x42A,0x602,0x626,0xCBC; 0x598,0x728,0x73C,0xF60,0xF69,0xF85.

## 3. Botões, atrasos e leitura de entrada

### Entrada (feita em prog_timer_int, 0x16F–0x19F — ver §5)
`F40` (K0, ativo em 0): K00=**R**, K01=**M**, K02=**L** (tamalib `hw.c`). Em RAM, ativos-altos: bit0=R, bit1=M, bit2=L.
- `M[0x26]` = botões pressionados agora (1=pressionado) (bits 0..2 = L,M,R).
- `M[0x27]` = máscara de **bordas de subida** acumuladas desde a última leitura (`copy_0x026_7_to_8_9` zera).
- `M[0x3D]`/`M[0x3E]`/`M[0x3F]` = auto-repeat: `M[0x3D]`=última leitura vista; `M[0x3E]` conta ticks com leitura inalterada (4 bits);
  ao dar a volta (16 ticks ≈ 436 ms) vira 8 e faz `M[0x27] |= atual & M[0x3F]` (repete a cada 8 ticks ≈ 218 ms);
  `M[0x3F]`=máscara de botões com auto-repeat (UI de ajuste de hora usa `0x6` = M e R; 0 desliga: escrito em 0x566/0x587).

### copy_0x026_7_to_8_9 (0x21–0x2B) — "read_buttons"
Saída: **A = M[0x26] (botões mantidos), B = M[0x27] (botões recém-pressionados)**; também grava `M[0x28]=A`, `M[0x29]=B`
(bits: 1=L,2=M,4=R), e zera `M[0x27]` (consome as bordas) dentro de seção crítica. Z/flags indefinidos.
16 chamadores (0x1F2,0x201,0x222,0x27B,0x296,0x2C3,0x3A0,0x569,0x56D,0x664,0x66E,0x81F,0x822,0x8B8,0x8F5,0x986).
```
u8 read_buttons(u8 *held,u8 *pressed){ cli(); A=M[0x26]; B=M[0x27]; M[0x27]=0; sei(); M[0x28]=A; M[0x29]=B; }
```
Idioma: `calz copy_0x026_7_to_8_9; fan mx,mask` testa botões novos em M[0x29] (X ficou em 0x29); ex.: loop_294 `fan mx,2` espera M.

### Atrasos (busy-wait em ticks de 27,24 ms)
- `M[0x22]` (lo), `M[0x23]` (hi): contador de 8 bits decrementado por tick do prog-timer; ao chegar a 0 permanece 0.
- `copy_xhl_to_0x022` (0x2C–0x34): `M[0x22]=XL, M[0x23]=XH` (seção crítica). 2 chamadores (0x3C, 0x396).
- `or_0x022_and_0x023` (0x35–0x3B): A = M[0x22] | M[0x23] (Z=1 se contador zerado). Chamadores 0x3D, 0x39A.
- `copy_xhl_to_0x022_or_loop_0x023` (0x3C–0x3F) = `delay_ticks(XH:XL)`: carrega e espera `while (M[0x22]|M[0x23]);` (sem HALT).
  7 chamadores (0x20,0x394,0x39D,0x645,0x68D,0x6AB,0x90D).
- `store_0x02_into_0x022_3` (0x1F–0x20): `X=2; delay_ticks(2)` e **cai em** `copy_0x026_7_to_8_9` (0x21): "delay 2 ticks (54 ms) e ler botões".
  Chamador 0x2B1. (Nome real: `wait_2ticks_read_buttons`.)
Pseudo-C: `void delay_ticks(u8 n){ tick22=n; while(tick22) idle(); }` — em C nativo, 1 tick = 27,24 ms de tempo emulado.

### label_31 / label_32 / label_33 (0xD4–0xDD) — "any_nibbles_set_2/3"
`clear_0x07D; A=M[Y]; Y++; [label_32: A|=M[Y]; Y++]; A|=M[Y]; set_f_0x07D` ⇒ A = OR de 2 (label_31) ou 3 (label_32) nibbles em Y,
Z=1 se todos zero (leitura atômica de contadores multi-nibble também escritos por ISR). label_31 usado em 0xF50,0xF81,0xF8E,0xFA3; label_32 em 0xF2E,0xF77,0xF88,0xFE5.
`label_33` é só o rótulo interno (A|=M[Y]).

## 4. Utilitários pequenos

- `zero_a_xp` (0xEF): `A=0; XP=0`. 56 chamadores. `zero_b_xp` (0xF2): `B=0; XP=0` (14). `one_a_xp` (0xF5): `A=1; XP=1` (17).
- `check_0xX5D_is_1` (0xF8–0xFA): `X=0x5D` (XP corrente); `cp mx,1`. Z=1 se M[XP:0x5D]==1. Chamadores 0xC85,0xC96,0xF11,0xF4A,0xF5E,0xFC2,0xFCA.
  M[0x5D] = **espécie/forma** (0=ovo, 1=bebê…; o estágio é M[0x50]) usado como índice (0x5D lido em 0x92A/0x93B antes das jump tables 0xC00/0xD00) (?).
- `springboard_label_238` / `label_38` (0xEC–0xEE): `[A=0]; pset 7; jp label_238 (0x7C0)`. Chamadores 0x374,0x509,0x983 (label_38) e 0x294,0x527,0x53E,0x555 (springboard).
- `label_35` (0xE2–0xE3) + `label_36` (0xE4–0xEB) + `label_37` (0xEA): **incrementa dois dígitos BCD "mm" com wrap em 60**:
  label_35: `X=0x12; D=1`. label_36: `M[X]++ (BCD, 4b); X++; M[X]+=carry; if (M[X] >= 6) M[X]=0; D=0`; saída **C=1 se não houve wrap**, C=0 se virou 00.
  Usos: tick de minuto na ISR (X vem de `ldpx mx,0` em 0x13F ⇒ X=0x12) e ajuste de minutos na tela de acerto de hora (0x573 ⇒ M[0x12..13]).
- `label_67/68/69` (0x1F4–0x1FF): **incrementa byte 8 bits em nibbles A(lo),B(hi) com wrap em 24** e grava em M[X],M[X+1]:
  `a++; b+=carry; if (b==0 || (b==1 && a<8)) store; else {a=0;b=0; store}` (valores 0x00–0x17, **binário/hex**, D=0 ⇒ horas 0–23).
  Chamadores: 0x146 (virada de hora), 0x580 (ajuste de hora; B&=1 antes). Entrada: A,B atuais, X=0x14. Trace s3: M[0x14],M[0x15] vão de 0x00…0x17 → 0x00.
- `label_66` (0x1EC–0x1F3): "arm timeout & flush input": `M[0x75]=0; M[0x76]=A; M[0x77]=B; M[0x57]=B; read_buttons();` (XP vem do chamador = 0).
  Chamadores 0x522 (A=1 ou 8, B=0xA/0xC), 0xE5D (A=2). M[0x57]=segundos de timeout (decrementado 1/s na clock ISR); M[0x75..0x77] = parâmetros de tela/estado (?).
- `label_282`-vizinhança/0x5A: ver RAM.

## 5. Vetores e ISRs

### Tabela de vetores (0x100–0x10F)
`jp` por vetor (E0C6S46: 0x100 reset, 0x102 clock timer, 0x104 stopwatch, 0x106 K0x, 0x108 K1x, 0x10A serial, 0x10C prog timer; ímpares nunca usados).
Mapeamento: 100→reset_vector(0x110), 102→clock_timer_int(0x11D), 10C→prog_timer_int(0x16F), todos os demais→generic_int(0x116).

### reset_vector (0x110–0x115)
`F=0; SP=0xFF; pset 2; jp reset_vect_cont (0x22A)` (continua fora da faixa: checa SVD, copia K0→M[0x270], limpa RAM, toca som `Y=0x80`,
se M pressionado no boot → modo teste 0x256, senão `label_294` espera M para começar — ver notas 0x200+).

### generic_int (0x116–0x11C)
Salva F,A,B,XP,XH,XL; `jp int_restore_ret`. (Nenhuma interrupção além de clock/prog é tratada.)

### int_restore_ret (0x15B–0x167) / gen_int_dis_int (0x168–0x16E)
`XP=0; if (M[0x7D]==0) { pop xl,xh,xp,b,a,f; ret /*sem set f,8*/ } else { pop…; set f,8; ret }`. (ver §1)

### clock_timer_int (0x11D–0x15A) — tick de 1 Hz
```
push f,a,b,xp,xh,xl; D=0;
(void)F00;                       // limpa fator de int do clock
F76=1; F77=0;                    // F76 bit0=WDRST: reinicia o watchdog. F77=0: cronômetro (SWRST/SWRUN) parado — não é ctl do relógio (datasheet, ver "Registradores de I/O usados")
F78=1; F79=2;                    // arma o prog timer (run, clock select 2); roda livre, a fase NÃO é reiniciada a cada 1 Hz
F12=1;                           // máscara: habilita int do prog timer
if (M[0x57]) M[0x57]--;          // timeout em segundos (ver label_66)
if (M[0x3C]) {                   // M[0x3C]!=0 => relógio rodando (ajustado)
    D=1; M[0x2E]=1;              // flag "passou 1 s" (consumida por UI/animação)
    M[0x10]++ (BCD); M[0x11]+=carry;           // segundos 00–59
    if (M[0x11] >= 6) {
        M[0x11]=0;
        if (!bcd_inc_minutes_label_36()) {      // minutos M[0x12..13], wrap 60
            hours = M[0x14] | M[0x15]<<4;       // 24h, binário (D=0 após label_36)
            hours = label_67(hours);            // wrap 24
        }
        label_312();                            // pset 0xC; call 0xC7A: tarefa por MINUTO (mexe nas necessidades) (?)
    }
    D=0;
}
// contador de 12 bits M[0x2F..0x31]++ a cada segundo (sempre, mesmo sem relógio)
if (++M[0x2F]==0 && ++M[0x30]==0 && ++M[0x31]==0) {   // overflow a cada 4096 s
    if (F70 & 3) { if (check_svd_voltage()) F70 = 0; }   // bateria baixa => sai do modo >3,1 V
}
goto int_restore_ret;
```
Observação: o comentário "TODO: Unused?" em 0x142 está errado: roda quando os minutos viram 60 (incremento de hora). Evidência:
trace s3 (hora) e `jp c,label_50` em 0x141 (C=1 = sem wrap). Segundos medidos: M[0x2F] +1 a cada 1,00 s (trace o), M[0x10]/M[0x11] só mexem após M[0x3C]≠0.
`M[0x3C]` é escrito: 0xF em 0x221 (boot "hard"), 0x58E (confirmar hora); 0 em 0x563 (entra na tela de ajuste de hora) e 0x1210 (init).

### prog_timer_int (0x16F–0x19F) — tick 256/7 Hz (27,34 ms)
```
push f,a,b,xp,xh,xl; D=0;
configure_buzzer();
(void)F02;                       // limpa fator
b = (~F40) & 7;                  // botões pressionados (1=pressionado)
M[0x5A]++;                       // contador livre 4 bits (entropia/aleatoriedade (?))
if (--M[0x22:0x23] underflow) M[0x22]=M[0x23]=0;   // delay_ticks()
a = M[0x26]; M[0x26]=b;
M[0x27] |= (a ^ b) & b;          // bordas de subida
if (M[0x3D] != b) { M[0x3D]=b; M[0x3E]=0; }
else if (++M[0x3E] == 16/*wrap*/) { M[0x3E]=8; M[0x27] |= b & M[0x3F]; }   // auto-repeat
goto int_restore_ret;
```

### check_svd_voltage (0x1E5–0x1EB) / check_svd_voltage_set_xp_f (0x1E3)
`F73=6; nop5; A=F73; F73=0; A&=8;` ⇒ Z=1 se bateria OK (>3,1 V), Z=0 se baixa. `_set_xp_f` antes faz XP=F. Chamadores: label_52 (0x157), reset_vect_cont (0x22B).

## 6. Buzzer / som

### Modelo
Sequenciador "tick a tick" em `configure_buzzer` (0x1A0–0x1C0, chamado no início de cada prog_timer_int ⇒ passo de 27,24 ms). Estado em RAM (XP=0):
- `M[0x32..0x33]` = **duração restante** (8 bits; passo dura valor+1 ticks).
- `M[0x34]` = frequência → F74 (bit 3 = 1 ⇒ passo **mudo**; só F74 recebe se bit3=0), `M[0x35]` = envelope → F75.
- `M[0x36..0x37]` = ponteiro (8 bits) para o próximo passo na tabela da **página E** (ROM `0xE00+ptr`), incrementado de 2 a cada busca; 0x7D = ocioso.
- `M[0x38..0x39]` = temporizador de "heavy load protection" (reload 0x58); `M[0x58..0x59]` = contador de repetição (M[0x59]==0xF ⇒ infinito).
- `M[0x7B]` = **som ligado** (0 ⇒ `play_sound` não faz nada; alternado por `xor mx,0xF` em 0x54D (menu), inicializado F em 0x120C).

### Tabela de passos (0xE7C jpba; 0xE7D…) — formato
`jp_table_0xE7D_buzzer` (0xE7C) = `jpba` ⇒ pula para `0xE00 + (B:A)`. Cada entrada é código executado in-place com `X=0x032`:
`lbpx mx,imm` (grava imm.lo em M[X], imm.hi em M[X+1], X+=2) e termina em `retd imm` (idem + retorna). Duas formas:
- **4 nibbles** (2 palavras: `lbpx dd; retd ff`): passo linear `{dur=dd (lo,hi), freq=ff.lo, env=ff.hi}`; ao retornar XL==6; o ponteiro (já +2) segue p/ a próxima.
- **6 nibbles** (3 palavras: `lbpx dd; lbpx ff; retd pp`): idem + novo ponteiro `pp` (salto/laço/fim) gravado em M[0x36..37].
Entradas notáveis: **0x7D** = ocioso `{dur FF, freq/env 08 (mudo), jump 7D}`; 0x80 = bipe longo (dur 0x30, f=3; tocado no reset);
0x83–0x90 = escala descendente f=7..1, dur 0 cada, terminando em 0x91 (`00 00 → 7D`); **0x94** = bipe curto de botão (dur 1, f=4 → 7D).
(Resto da tabela: fora desta faixa, 0xE7D–0xEAD+; dados = efeitos sonoros — manter como tabela de tuplas.)

### configure_buzzer (0x1A0–0x1AA, loop_59 0x1AB–0x1C0)
```
void configure_buzzer(void){            // XP=0
  if (dur(M32|M33<<4) != 0) { dur--; if (M[0x34]&8) goto buzzer_off; return; }
  dur--;                                // underflow para 0xFF mas será sobrescrito
loop:
  p = M[0x36]|M[0x37]<<4; M[0x36..37] = p+2;     // 8 bits
  X=0x32; step_table_E[p]();                     // escreve 4 ou 6 nibbles a partir de M[0x32]
  if (XL==6 || M[0x59]==0xF) goto buzzer_control;          // passo linear ou repetição infinita
  cnt = M58|M59<<4; cnt--; if (cnt had no borrow) goto buzzer_control;   // salto com repetições restantes
  M[0x36]=0xD; M[0x37]=0x7;                      // acabou: ponteiro=0x7D
  goto loop;                                     // busca o passo ocioso
buzzer_control:
  if (M[0x34]&8) goto buzzer_off;
  M[0x38]=8; M[0x39]=5;                          // 0x58: timeout da proteção de carga
  F71 |= 1;                                      // heavy load protection ON
  F74 = M[0x34]; F75 = M[0x35];
  F54 &= 7;                                      // liga saída do buzzer (R43)
  return;
buzzer_off:  (0x1D7)
  M[0x38..39]--(8 bits); if (underflow) F71 &= 0xE;   // desliga proteção após ~88 ticks mudo
  F54 |= 8;                                       // desliga saída do buzzer
}
```
Na reescrita: tocar `play(table)`; frequência = F74 (BZFQ), envelope F75; a saída só precisa dos tons/durações. Chamado só pela prog_timer_int.

### Disparo de som — rotinas "play_sound" (0xB7–0xCD)
Todas respeitam `M[0x7B]` (retornam sem fazer nada se 0). Efeito (clear_0x32_store_yhl, 0xC2–0xCC, seção crítica):
`M[0x32]=M[0x33]=0` (força busca no próximo tick); `M[0x36]=YL; M[0x37]=YH` (ponteiro); `M[0x58]=A; M[0x59]=B` (contagem de repetições).
Entradas (XP é forçado a 0):
- `if_0x7B_set_clear_0x32_store_0x94_to_0x036_7_set_0x059_to_0xF` (0xBB) = **`play_beep()`**: `Y=0x94`, depois cai em 0xBC. 16 chamadores (botões/UI: 0x27F,0x2D0,0x2DB,0x2E1,0x3B2,0x3CB,0x508,0x553,0x572,0x579,0x586,0x67D,0x6C5,0x82A,0x833,0x8FE).
- `if_0x7B_set_clear_0x32_store_yhl_set_0x059_to_0xF` (0xBC) = **`play_sound(Y)`**: A=0,B=0xF (laço infinito até a sequência apontar 0x7D). 12 chamadores (0x21B,0x23A (boot, Y=0x80),0x381,0x387,0x38A,0x39F,0x641,0x668,0x6A7,0x6C9,0x6CE,0xAE8).
- `if_0x7B_set_clear_0x32_store_yhl` (0xBF) = `play_sound_n(Y, A, B)` genérico (contagem de repetições A|B<<4; B≠F ⇒ finita).
- `xp_0_if_0x7B_set_clear_0x32_store_yhl` (0xB7, B=0, XP=0; e 0xB9 inalcançável): `play_sound_n(Y, A, 0)`. Chamadores 0x31A,0x34D,0xFF1.
Pseudo-C: `void play_sound(u8 ptr){ if(!M[0x7B]) return; dur=0; seq_ptr=ptr; repeat=0xF?; }` (ptr = YL/YH).

### Ciclos por instrução — conferidos no manual do núcleo
Fonte: *E0C6200/6200A Core CPU Manual* (Epson, 96 p.; https://download.epson-europe.com/pub/electronics-de/asmic/4bit/60family/62core_e.pdf), tabela 3.1.1 (instruções por função).
Comparei a coluna "Clock" do manual com o campo `cycles` da tabela `ops[]` de `harness/tamalib/cpu.c`: das 76 instruções lidas automaticamente, **todas batem**, exceto `SLP`, que o TamaLIB não implementa (o P1 não a usa). ## 8. Para a reescrita (resumo)
1. **Descartar**: seção crítica 0x07D, jpba/retd como mecanismo (viram arrays), copy_video em pares (mapeamento VRAM), delay busy-wait (vira contador de ticks do simulador).
2. **Manter**: clock de 1 Hz (M[0x10..0x15]: seg BCD, min BCD, hora 0–23), contador de segundos 12 bits (só afeta bateria — irrelevante), tick de 27,24 ms
   (botões, auto-repeat 16/8 ticks, delay, som), `M[0x57]` timeout, `M[0x2E]` flag de segundo, sequenciador de som (tabela da página E).
3. **Interface**: `read_buttons() -> (held,pressed)`; `delay_ticks(n)`; `play_beep()/play_sound(ptr)`; `draw_sprite(buf,page,idx)`; `present()` (framebuffer 32×16 + 8 ícones).
