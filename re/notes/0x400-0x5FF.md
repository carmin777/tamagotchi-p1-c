# ROM 0x400–0x5FF — animação do pet, tela principal, relógio

Convenções: `M[a]` = nibble de RAM; `{M[b]:M[a]}` = byte (a = nibble baixo). `XP:XH:XL` = ponteiro X de 12 bits.
`pset N; call/jp s` = salto para `N*0x100+s`. `jpba` salta para `{NP,B,A}` (tabela de salto por B:A, NP vem do `pset` anterior).
`retd imm` = retorna gravando `imm&F` em M[X], `imm>>4` em M[X+1], X+=2 (usado como tabela de dados de 8 bits).
`lbpx mx,imm` = grava 2 nibbles em M[X],M[X+1] e continua (não retorna). Combinação `lbpx…; retd` = entrada longa de tabela.
Flags: C=bit0, Z=bit1, D=bit2, I=bit3 (`set f,8` liga IRQ). Botões (K0): bit0=R (cancela), bit1=M (confirma), bit2=L (seleciona).
Evidência de máquina: traces em `out/sub400*/` (baby0.sav) — citadas onde usadas.

Esta faixa contém (a) o motor de animação do pet (`reset_pet_animation`, `step_pet_animation`), (b) overlays da tela do pet
(sono/doente/cocô), (c) o loop da tela principal com o menu de ícones, (d) a tela de acerto do relógio, (e) desenho do relógio.
Não há tabelas de dados de jogo nesta faixa (só `nop7` de padding em 0x4FE-4FF e 0x5FE-5FF; as tabelas usadas ficam em 0x98B, 0xA00, 0xB00, 0xBC0, 0xC00, 0x15E6).

## Modelo do buffer de vídeo (necessário para ler tudo abaixo)
- Buffer em RAM página 1: 0x100–0x1FF = 64 colunas x 16 linhas, 2 nibbles/coluna (nibble baixo = 4 linhas de cima do bloco de 8).
  - Metade de cima (linhas 0-7): 0x100–0x13F = página ESQUERDA (colunas 0-31), 0x140–0x17F = página DIREITA (32-63).
  - Metade de baixo (linhas 8-15): 0x180–0x1BF = esquerda, 0x1C0–0x1FF = direita.
- `{M2B:M2A}` (0x02A/0x02B) = "view ptr" = deslocamento (em nibbles) da janela de 32 colunas que `copy_video_buf_to_vram` (calz 0x56) copia
  para o LCD (0xE00/0xE80): lê `0x100+ptr .. +0x3F` e `0x180+ptr .. +0x3F`. ptr=0x00 mostra a página esquerda; ptr=0x40 a direita;
  valores intermediários = rolagem. `clear_page_0x100` (calz 0x40) zera tudo e põe ptr=0; `label_30` (calz 0xCE) põe ptr=0x40.
- Convenção do jogo: tela do pet é desenhada na página ESQUERDA; telas "modais" (relógio, menus) na DIREITA (ptr=0x40). Transição = rolagem
  (`scroll_view_left` / `scroll_view_right`, ver abaixo).
- Tile de 16 nibbles ("tile 8x8"): `misc_render(B:A=v)` (0x7A5) desenha 16 nibbles em M[X..X+15]: v<64; v>=64 apaga. Endereço do gráfico:
  página 0x16 se v<32 senão 0x17, offset `(v&0x1F)*8` (tabela de nomes no fim do arquivo).

## 1. `draw_pet_screen_overlays` — 0x400–0x464 (agg23: `copy_buf_and_render_misc`; comentário dele "copia buffer p/ VRAM" está ERRADO: só desenha no buffer)
Chamada a cada quadro da tela do pet depois de `step_pet_animation` (via `calz 0x54` = `calz_copy_buf_and_render_misc`, que depois cai em
`copy_video_buf_to_vram`). Desenha sobre a página esquerda: apagão (luz apagada), Z de sono, caveira de doença, e a pilha de cocôs.
Chamado por: 0x055 (stub calz 0x54), 0x50F, 0x635. Chama: `misc_render`(0x7A5), `check_0x04A_highbit`, `bit_high_at_0x048`, `one_a_xp`.
RAM: lê M[4B], M[4A], M[48], M[4D]; escreve M[4A] (contador), M[7E] (contador de quadros), buffer 0x100–0x1BF, M[3],M[4] (temporários).
```c
void draw_pet_screen_overlays(void) {
  if (M[0x4B] == 0) {                       // luz apagada (?: 0x4B=1111 luz acesa; zerado quando apaga a luz, ver 0x359 que põe F ao acordar)
    fill(0x100..0x13F, 0xF); fill(0x180..0x1BF, 0xF);        // tela preta (apaga o pet que foi desenhado)
    if (M[0x4A] & 8) {                      // dormindo (M4A=F ao dormir/ 0 ao acordar: 0x30C, 0xF1F)
      M[0x4A] = (M[0x4A] + 1) | 8;          // 8..F cíclico (anim)
      misc_render(v = 0x20 + ((M[0x4A]>>1)&1), at X=0x120); // 0x1700/0x1708: "Z" fundo preto
    }
    return;
  }
  if (M[0x4A] & 8) {                        // dormindo, luz acesa
    M[0x4A] = (M[0x4A] + 1) | 8;
    misc_render(v = 0x3A + ((M[0x4A]>>1)&1), at X=0x130);   // 0x17D0/0x17D8: "Z" fundo claro
  } else if (M[0x48] & 8) {                 // doente (M48 bit3: caveira)
    misc_render(v = 0x22, at X=0x130);                      // 0x1710 caveira
  }
  // cocôs
  M[0x7E]++;                                // contador de quadros (4 bits, livre)
  M[4] = 0xE + ((M[0x7E]>>1)&1);            // 0xE/0xF -> troca a cada 2 quadros
  M[3] = n = min(M[0x4D], 8);               // número de cocôs (M4D, máx 8) 
  if (n >= 3) {                             // desloca a página esquerda p/ a esquerda para liberar colunas
    k = ((n-3)>>1) + 1;                     // n=3,4->1  5,6->2  7,8->3
    memmove(0x100..0x13F  <- 0x100+16k ..), memmove(0x180..0x1BF <- 0x180+16k ..);   // 64 nibbles cada; k*8 colunas
  }
  // desenha n tiles de cocô (v = 0x10 + M[4] = 0x1E/0x1F -> 0x16F0 "cocô →" / 0x16F8 "cocô ←") em
  // X = 0x1B0,0x130,0x1A0,0x120,0x190,0x110,0x180,0x100 (nessa ordem: 1º embaixo à direita, 2º acima dele, ...)
}
```
Detalhes: o deslocamento lê além de 0x13F/0x1BF (para k>=1 puxa lixo da página direita), mas essa região é sobrescrita pelos tiles de cocô
(n>=3 -> tiles em 0x1B0,0x130,0x1A0 cobrem k=1; n>=5 cobre k=2; n>=7 cobre k=3). Hipótese (?): o pet é desenhado já considerando o
deslocamento (posições nas tabelas de movimento) — não verificado. M4A: nibble de sono: bit3 = dormindo, bits0-2 = fase da animação do Z
(confirmado: 0x30C põe F ao dormir, 0xF1F põe 0 ao acordar, junto de M4B=F).
Traces: M[7E] sobe 1 por quadro (~0.45 s) e M[4] alterna E/F a cada 2 (out/sub400c/writes.tsv, pc 0434/0439).

## 2. `reset_pet_animation` — 0x465–0x481 (agg23 `label_142`); thunks 0x482–0x485
Reinicia o motor de animação para o par (estágio, tipo de anim) atual. Entrada: M[5D] = estágio de vida (0=ovo, 1=bebê, … ; evidência:
ovo M5D=0, bebê M5D=1 nos dumps out/boot_egg.sav / baby0.sav), M[5E] = conjunto de animação (1=normal, 3=dormindo, 9=doente, 5 = outra,
ver `select_pet_anim_set`). Chamado em: 0x21F, 0x36E, 0x5A4, 0x630, 0x663, 0x8B7, 0x982, 0xFFC.
```c
void reset_pet_animation(void) {
  M[0x5F] = 0;                              // timer de pose
  M[0x66] = M[0x67] = 0;                    // timer de movimento
  idx = (M[0x5D] << 4) | M[0x5E];
  {M[0x6F]:M[0x6E]} = TBL_0xA00[idx];       // 2 ids de sprite (nibbles): 6E = "quadro 0", 6F = "quadro 1"   (call 0xABD = jpba, página A)
  {M[1]:M[0]}       = TBL_0xB00[idx];       // M0 = índice do script de pose (tab 0xBC0), M1 = índice do script de movimento (tab 0x98B)
  {M[0x6B]:M[0x6A]} = TBL_0x98B[M[1]];      // ptr inicial do script de MOVIMENTO (byte baixo, página 9)   -> thunk 0x482 (pset 9; jpba)
  {M[0x65]:M[0x64]} = TBL_0xBC0[M[0]];      // ptr inicial do script de POSE (byte baixo, página B)        -> pset B; jpba
}
```
(O índice `0x98B+M1` vem de `a=M1+0xB, b=8+carry`; `0xBC0+M0` de `b=0xC`.) Os destinos X são 0x6E, 0x00, 0x6A, 0x64 — os `retd` dos
alvos gravam direto lá. M[0..1] são só temporários. Não zera a posição {M6D:M6C}.
Exemplo (traces, bebê): TBL_A00[0x11]=0x15 -> sprites 5 e 1; M64 oscila 0xA/0xB/0xC conforme o script de pose (out/sub400c).

## 3. `step_pet_animation` — 0x486–0x4E2 (agg23 `label_145`); thunks 0x4E3–0x4E6
Um passo por quadro: avança os dois scripts (pose e movimento), calcula posição e desenha o pet (metade de cima e de baixo) no buffer
em `{M3B:M3A}` (página 1). Chamado de: 0x053 (`label_13`), 0x50D, 0x633, 0x66B, 0x8BB. Chama: `jp_table_0xB00_2`(0x4E3), `jp_table_0x980_2`(0x4E5),
`label_288`(0x928: desenha metade de cima), `label_289`(0x939: metade de baixo) — ambos consultam tabelas 0xC00/0xD00 por M[5D] e chamam `render_asset`.

Estado (RAM, todos nibbles):
| addr | significado |
|---|---|
| 5F | timer da pose (quadros restantes; duração = delay+1) |
| 62 | nibble baixo do byte de pose lido = delay (vai p/ M5F); 63 = nibble alto = flags da pose |
| 64/65 | ponteiro (8 bits) no script de pose, página 0xB (`{65:64}`) |
| 66/67 | contador (8 bits) do passo de movimento; M67 é zerado após carregar e seu valor vai para M70 |
| 68/69 | argumento de movimento do passo atual (`{69:68}`): bit0 = relativo; resto = posição/delta |
| 6A/6B | ponteiro no script de movimento, página 9 (avança de 2 em 2) |
| 6C/6D | posição atual do pet (offset de nibble no buffer, 8 bits) |
| 6E/6F | ids de sprite (2 quadros) vindos de TBL_A00 |
| 70 | flags de movimento (nibble alto do 1º byte do passo): bit3 = desenha metade de cima, bit2 = desenha metade de baixo, bit1 = espelha cima, bit0 = espelha baixo |
| 3A/3B | cópia de 6C/6D = destino do desenho (X = 0x1:{3B}{3A}) — também reaproveitado como destino do relógio |
Flags da pose M63: bit1 escolhe sprite da metade de CIMA (0 -> M6E, 1 -> M6F), bit0 escolhe da metade de BAIXO; bit3/bit2 = inversão (xor) de espelhamento de cima/baixo.
```c
void step_pet_animation(void) {
  // --- script de pose (página 0xB): cada entrada = 1 byte {flags(hi), delay(lo)} ---
  if (M[0x5F] == 0) {                       // add mx,0xF não gera carry => era 0
    p = {M[0x65]:M[0x64]}; {M[0x65]:M[0x64]} = p + 1;
    TBL_PAGE_B[p] -> retd grava {M[0x63]:M[0x62]};   // entradas "lbpx byte; retd ptr" regravam M64/65 (salto/loop)
    M[0x5F] = M[0x62];
  } else M[0x5F]--;
  // --- script de movimento (página 9): entrada = 2 bytes ---
  c = {M[0x67]:M[0x66]};
  if (c == 0) {                              // era 0 => busca
    p = {M[0x6B]:M[0x6A]}; {M[0x6B]:M[0x6A]} = p + 2;
    TBL_PAGE_9[p] -> grava M66,M67 (byte0: lo=delay, hi=flags) e M68,M69 (byte1: argumento) ; entradas de salto também regravam M6A/6B
    M[0x70] = M[0x67]; M[0x67] = 0;
    // (o contador é M66 após carga: o passo dura M66+1 quadros; o decremento acima faz {67:66}-- e só busca quando estava em 0)
  } else { {M[0x67]:M[0x66]} = c - 1; }
  // posição: executada TODO quadro
  arg = {M[0x69]:M[0x68]};
  pos = (arg & 1) ? ({M[0x6D]:M[0x6C]} + (arg & 0xFE)) : arg;      // relativo (delta acumulado por quadro, 8 bits mod 256) ou absoluto
  {M[0x6D]:M[0x6C]} = pos;  {M[0x3B]:M[0x3A]} = pos;
  // desenho
  if (M[0x70] & 8) {                         // cima
    sprite = (M[0x63] & 2) ? M[0x6F] : M[0x6E];
    flip   = (M[0x70]<<2 ^ M[0x63]) & 8;     // = M70.bit1 ^ M63.bit3 em bit3
    label_288(sprite, flip);                 // 0x928: desenha em X={3B:3A}, página 1
  }
  M[0x3B] += 8;                              // = +0x80: metade de baixo (vê-se: ldx 0x3B add 8)
  if (M[0x70] & 4) {                         // baixo
    sprite = (M[0x63] & 1) ? M[0x6F] : M[0x6E];
    flip   = ((M[0x70]<<2 ^ M[0x63]) << 1) & 8;   // M70.bit0 ^ M63.bit2
    label_289(sprite, flip);
  }
}
```
Notas/evidência: (1) o salto-ou-busca do movimento usa `add mx,0xF; adc mx,0xF` em {67:66}: quando valor !=0 sempre há carry (decrementa),
quando 0 vira 0xFF e cai na busca (trace: M66/M67 vão a F e logo são regravados por 09BB: `0.190 0497 066 0->F; 0.193 09BB 066 F->0, 067 F->C`).
(2) M3B é incrementado em 8 e NÃO restaurado: ao fim do quadro {3B:3A} aponta a metade de baixo (o próximo quadro recalcula).
Observado: M70=C (0xC=1100b: cima+baixo, sem espelho) no trace do bebê. Bit 0/1 de M70 e bits 2/3 de M63 só inferidos do código (?).
(3) Entradas de movimento do bebê (0x99B…): `lbpx 0xC0; retd 0x12` = {delay 0, flags C} + posição absoluta 0x12 (nibbles = coluna 9);
`lbpx 0xC1; retd 0xFB` = delay 1, relativo, delta 0xFA (-6 nibbles = -3 colunas/quadro); `lbpx 0xCF; lbpx 0x10; retd 0x9B` = fica 16 quadros em 0x10 e volta ao 0x99B.
(4) Entradas de pose: `retd 0x01` (delay 1, flags 0), `lbpx 0x31; retd 0xCA` (flags 3 delay 1 + salta ptr p/ 0xCA) em 0xBCA/BCB — laço de 2 poses.
Os dados dessas tabelas (0x98B..0x9FF, 0xA00, 0xB00, 0xBC0..0xBFF) são de outras faixas; o formato está acima.

Thunks: `jp_table_0x980`(0x482), `jp_table_0xB00`(0x484), `jp_table_0xB00_2`(0x4E3), `jp_table_0x980_2`(0x4E5): `pset 9|B; jpba` — o `retd` do alvo retorna ao chamador do thunk.

## 4. `enter_clock_screen_from_pet` — 0x4E7–0x4FD (agg23 `label_155`)

void enter_clock_screen_from_pet(void) {

## 5. `scroll_view_left` — 0x500–0x507 (agg23 `label_156`)
Entrada: B = passo. Mostra o buffer rolando a janela para a ESQUERDA a partir do ptr atual até 0 (efeito de transição para a tela do pet).
```c
void scroll_view_left(uint4 B) {
  do {
    copy_video_buf_to_vram();                        // calz 0x56
    lo = M[0x2A] + B;  M[0x2A] = lo & 15;
    hi = M[0x2B] + 0xF + (lo>>4); M[0x2B] = hi & 15;
  } while (hi > 15);                                 // ptr -= (16-B)  (aritmética de 8 bits); sai quando "emprestar"
}
```
Com B=0xC (passo 4 nibbles = 2 colunas) a partir de 0x40: 17 cópias (ptr 0x40,0x3C,…,0x00); B=0xE: passo 2. Ao sair, ptr = 0xFC (ou 0xFE) — quem
chama deve chamar `clear_page_0x100` antes de voltar a usar o ptr. Chamado em 0x3CE (B=E), 0x511 (B=C), 0x648 (B=C).
Contraparte: `label_305` (0xAF0) = `scroll_view_right(A=limite do nibble alto de ptr, B=passo)`: ptr=0; repete {copiar; se M2B>=A sair; ptr+=B}.

### 6.2 `pet_screen_loop` — 0x512–0x54C (`label_158`..`label_165`)
```c
label_158: if (M[0x7C] == 0) hatch();             // label_391 @0xFEC: M7C=F, som, M5D=M5E=1, reset_pet_animation, animação de nascimento (outra faixa)
label_159: M[0xA0] = 0;                           // cursor memorizado := nenhum ícone
label_160: B = 0xA; A = (M[0x7C] == 0xF) ? 8 : 1;  // 8 posições (0..7) se chocado; 1 (só 0) se ainda ovo
           menu_init(A, B);                       // label_66 @0x1EC: M75=0 (cursor), M76=A (limite), M77=B (recarga do timeout), M57=B, descarta eventos de botão
           M[0x75] = M[0xA0]; set_icon_highlight(M[0xA0]);   // 0x7C0: A=1..7 acende o ícone (máscara tab 0x7D8: 0,1,2,4,8,0x10,0x20,0x40,0x80)
label_162: for(;;) {
             if (M[0x7C] == 0) goto label_158;    // ovo chocou (contador chegou a 0)
             if (M[0x5C] != 0) {                  // label_357 @0xF00: devolve NZ se há evento pendente
                 event_dispatch();                // jump_table_0x300 (0x307): A=M5C; M5C=0; jpba -> 0x301..0x306 (acorda, adoece, cocô, …)
                 goto label_159;
             }
             (A=cursor, flags) = menu_poll();     // label_94 @0x2C3
             if (M[0x28]==5 && (M[0x29] & 5)) {   // L+R seguros e evento de L ou R
                 M[0x7B] ^= 0xF;                  // liga/desliga SOM (7B=F som on)
                 buzzer(ptr=0x97, M58=A, M59=0xF); goto label_159;     // label_166
             }
             if (flags.C) goto label_159;         // R (cancela) ou timeout => cursor volta a 0
             if (flags.Z) {                       // M (confirma)

                 pset 7; jpba(B:A = 2*A) -> tabela 0x700, 2 palavras por entrada (pset N; jp label)
             }
             // nada / L moveu cursor:
             set_icon_highlight(A);
             clear_page_0x100();

```
Tabela de saltos 0x700 (cursor → destino; ícone por ordem do P1; nomes marcados (?) por inferência de código):
0 → 0x4E7 relógio (sem ícone); 1 → label_220 0x710 comida (?); 2 → label_297 0xABE luz (lê M4B, alterna M78) ; 3 → label_196 0x624 jogo
(recusa se dormindo/doente: checa M4A/M48); 4 → label_191 0x600 remédio (?); 5 → label_336 0xD7E banheiro (?); 6 → label_247 0x814 status
(4 páginas, contador M80); 7 → label_301 0xADA disciplina (?). Entradas 1..7 voltam ao loop via `jp label_160` (0x623,0x721,0x835,0xAD9,0xAEF,0xD93 ...).
Chamado por: 0x2B4/0x2BB (de 0x2xx, vindo do relógio) e retorno de menus (`jp label_160`/`label_159`).
Evidência (trace out/sub400d, baby0.sav): cada `press L` escreve M28/M29=4 (bit2), M57: 9->A (recarga) e M75: 0→1→2→3 (pc 02D4); M é dispatch (pc 0666 grava M57=F no destino do cursor 3).
Timeout: M57 é decrementado 1x/s pela interrupção do relógio (pc 0132) e recarregado com M77 a cada botão; zero ⇒ `menu_poll` devolve C=1 (cancela).

`menu_poll` (label_94, 0x2C3, fora da faixa, mas necessário): lê eventos (`copy_0x026_7_to_8_9`: A=M26 estado dos botões segurados; M27 = eventos
de pressão, zerado ao ler; ambos copiados para M28/M29). Devolve A=cursor M75, flags: L (M29 bit2): beep, M75=(M75+1)<M76 ? M75+1 : 0 → C=0,Z=0;
M (bit1): beep, C=0,Z=1; R (bit0): beep, C=1,Z=1; sem botão e M57==0 e M77!=0: C=1,Z=0 (timeout). Qualquer botão recarrega M57=M77 (se M77!=0).
ISR (0x18B–0x19E): M26 = nível, M27 |= novos apertos, e auto-repetição após 8 ticks com máscara M3F.

### 6.3 `toggle_sound` — 0x54D–0x552 (`label_166`): `M7B ^= 0xF; B=F; Y=0x97; clear_0x32_store_yhl` (bipe mesmo desligando, pois essa
entrada não testa M7B); `jp label_159`.

## 7. Tela de ajuste do relógio — 0x553–0x590 (`label_167`..`label_174`)
Entradas: 0x2B7 (A==5: L+R seguros na tela do relógio) e 0x98A (laço inicial de partida; ver roteiro scripts/boot_set_clock.txt: M no ovo).
```c
void set_clock_screen(void) {              // label_167
  beep_click(); set_icon_highlight(0); clear_page_0x100();
  X = 0x1E0; misc_render(0x0C); misc_render(0x0D);     // 0x1660 "S|" + 0x1668 "ET" = texto "SET" (canto inferior direito da página direita)
  M[0x3C] = 0;                  // relógio PARADO (a ISR de 1 Hz só conta segundos se M3C != 0; confirmado em 0x133-0x13A)
  M[0x10] = M[0x11] = 0;        // segundos := 00
  M[0x3F] = 6;                  // máscara de auto-repetição (M e L repetem se segurados; ver ISR 0x19A)
  draw_clock_screen();          // label_175
  while (held_buttons() != 0);  // label_168: espera soltar tudo (A=M26)
  for(;;) {
    draw_clock_screen();        // label_169
    for(;;) {                   // label_170
      poll();                   // copy_0x026_7_to_8_9 (A=segurados, M29=eventos)
      if (M29 & 1) { beep; M3F = 0; /* se M15>=2 → 0x97F (nunca ocorre: hora<24) */ M3C = 0xF; goto clock_screen_loop; }   // R: confirma; relógio passa a andar
      if (M29 & 2) { beep; minutes_inc_wrap60(); M2E = 0xF; }    // M: +1 min (label_35 @0xE2: BCD em M12/M13, D=1; M13>=6 => 0; NÃO carrega para hora)
      if (M29 & 4) { beep; hour = {M15&1:M14}; hour = (hour+1 >= 24) ? 0 : hour+1; store; goto redraw; }   // L: +1 h (label_67 @0x1F4)
      if (M2E == 0) continue;   // nada mudou
      break;                    // redraw
    }
  }
}
```
Hora em M14 (nibble baixo) / M15 (nibble alto) em BINÁRIO (0..23, `{15:14}`), minutos BCD M12/M13, segundos BCD M10/M11. M2E = "relógio mudou, redesenhar"
(a ISR de 1 Hz põe 1; `draw_clock` zera). Evidência: scripts/boot_set_clock.txt (L=+1h, M=+1min, R=confirma) e dump out/sub400e (M2A/2B=0/4, M3A/3B=4/C).

## 9. `draw_clock` — 0x5A6–0x5E2 (`label_181` + `render_clock_values`)
Desenha hora no buffer a partir de X = 0x1:{M3B:M3A} (normalmente 0x1C4). Chamado em 0x29A, 0x4F3, 0x593.
```c
void draw_clock(void) {
  X(xp=0); IRQ off (clear_0x07D);
  M[0x2E] = 0;
  m4=M[0x10]; m5=M[0x11]; m6=M[0x12]; m7=M[0x13]; A=M[0x14]; B=M[0x15];    // snapshot atômico (seg, min, hora)
  IRQ on (set_f_0x07D);
  hour24_to_12h(A,B);                           // -> M8 (unidade), M9 (dezena bits0-1 | PM<<3)    (X=8)
  X = 0x100 | {M3B:M3A};                        // XP=1
  misc_render(v = 0xA + ((M9>>3)&1));           // 0x1650 "AM" / 0x1658 "PM" (vertical) – 16 nibbles na metade de baixo
  clear_16_addrs();                             // mais 16 nibbles em branco
  X += 0x60 (com wrap de 8 bits, xh += 6): vai p/ metade de cima: (0x1C4 → 0x144)
  if (M9 & 3) glyph_big(M9 & 3); else clear_8();       // dezena da hora (vazio se 0)
  blank(2); glyph_big(m8);                             // unidade da hora
  blank(2) ; col(0x22) ; blank(2)                       // ':' (3 colunas: 00 22 00)
  glyph_big(m7); blank(2); glyph_big(m6);               // minutos
  blank(4); glyph_small(m5); blank(2); glyph_small(m4);// segundos (fonte pequena = índice +10)
}
// glyph_big(d)  = render_asset(page 0x15, off = 4*d)          (0x1500+4d, 8 nibbles) -> setup_addr_and_render_clock
// glyph_small(d)= render_asset(page 0x15, off = 4*(d+10))     (0x1528+4d)            -> render_clock_with_b_0
```
Soma de nibbles: 8+2+8+6+8+2+8+4+8+2+8 = 64 (largura total 32 colunas, começando em 0x144 → os 2 últimos nibbles... os 4 últimos nibbles invadem 0x180–0x183 (?); confirmado
o início em 0x144 e a posição do ':' em 0x156–0x15B no dump out/sub400e/ram.txt: `158: 22`).
Em `enter_clock_screen_from_pet` os segundos (0x170–0x17F) são apagados depois.

### 9.1 `hour24_to_12h` — 0x5E3–0x5EE (`label_184`..`label_186`)
Entrada B:A = hora 0..23 como byte binário (A=nibble baixo, B=alto) e X=8. Se B<1 ou (B==1 e A<8): `{m1:m0} = (B:A) + 0xE6` (0xE6 = `+6` no nibble baixo, `+0xE` no alto, com carry) e
`m2=5` → `render_asset` na página 0x15, que cai em `retd` da tabela de 24 entradas em 0x15E6:
`h=0→0x12, 1..9→0x01..0x09, 10→0x10, 11→0x11, 12→0x92, 13..21→0x81..0x89 (pm: 0x80|h-12), 22→0x90, 23→0x91`.
Saída: M[8] = nibble baixo (unidade BCD), M[9] = nibble alto: bits0-1 dezena (0/1), bit3 = PM. Hora inválida (>=24) → `retd 0` (M8=M9=0).

### 9.2 `render_clock_with_b_0` 0x5EF / `setup_addr_and_render_clock` 0x5F3 / `render_clock_page` 0x5FB
```c
render_clock_with_b_0(A):  B=0; (B:A) = A + 10;  goto skip;     // fonte pequena
setup_addr_and_render_clock(A): B=0;
skip: (B:A) <<= 2;  M0=A; M1=B;  A=5;
render_clock_page: M2=A; pset 0; jp render_asset;               // render_asset (0x000): página (M2&7)*4 na tabela 0x1000; M1:M0 = offset. M2=5 => 0x15xx
```
Chamado por: 0x5D0-0x5E2 (draw_clock) e 0x2AA (render_clock_with_b_0, no loop do relógio).
