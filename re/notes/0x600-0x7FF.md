# ROM 0x600–0x7FF

Convenções: `M(a)` = nibble da RAM no endereço `a` (XP:XH:XL); `A,B` = registradores; `C,Z,D` = flags.
"page 0" = `calz` (0x000–0x0FF). Labels `label_N` são do agg23. `(?)` = hipótese.
Verificado com o emulador (`harness/trace`, ROM com o `jp nc,label_294` de 0x58C trocado por nop7 só para
poder passar da tela de acerto de relógio e chegar ao loop principal; nada dentro de 0x600–0x7FF foi alterado).

## Visão geral
Esta faixa contém, quase toda, **handlers das ações do menu principal** (medicina, jogo de adivinhar,
comida), a **inicialização de "novo jogo"** (`label_232`), o **renderizador de tiles 8x8** (`misc_render`)
e a **rotina que acende os ícones do LCD** (`label_238/242`).

### Dispatch do menu principal (como se chega aqui)
`label_164` (0x543, fora da faixa) guarda `M(0x0A0)=n` e faz `pset 7; jpba` com `B:A = 2*n` → tabela em 0x700.
`n = 0` (nenhum ícone selecionado) e `n = 1..7` = ícone `n-1` aceso no LCD (`n=8` volta a 0).

| n | ícone LCD | alvo (0x700+2n) | rotina |
|---|---|---|---|
| 0 | nenhum (mostra relógio/idade? tela `label_155`, pg 4) | 0x700 `pset 4; jp label_155` | fora da faixa |
| 1 | 0 comida | 0x702 `pset 7; jp label_220` | `food_menu` 0x710 |
| 2 | 1 luz | 0x704 `pset A; jp label_297` | fora (0xAxx): luz liga/desliga (`M(0x4B)`=F/0) |
| 3 | 2 jogo | 0x706 `pset 6; jp label_196` | `play_guess_game` 0x624 |
| 4 | 3 remédio | 0x708 `pset 6; jp label_191` | `medicine_action` 0x600 |
| 5 | 4 banheiro | 0x70A `pset D; jp label_336` | fora |
| 6 | 5 status/medidor | 0x70C `pset 8; jp label_247` | fora |
| 7 | 6 disciplina | 0x70E `pset A; jp label_301` | fora (0xADA): zera `M(0x209)`, `M(0x43)+=4` |

(ícone 7 = "atenção", não selecionável, é só aceso por `label_238`.)  Evidência: `cov.bin` após `L×k, M`: k=1→0x702/0x710,
k=3→0x624.., k=4→0x600.., k=7→0x70E; k=8→0x700.

Todos os handlers terminam com `pset 5; jp label_160` (0x51A, volta ao menu mantendo o ícone) ou
`jp label_159` (0x517, zera `M(0x0A0)` = deseleciona e volta ao ocioso).

### Botões (`M(0x029)` depois de `copy_0x026_7_to_8_9`)
bit0 (valor 1) = **R** (cancela), bit1 (2) = **M** (confirma), bit2 (4) = **L** (seleciona/avança).
Evidência: jogo grava `M(0x081)=4` ao apertar L; `label_94`: `fan mx,4`→avança cursor.

## 0x600–0x61D `medicine_action` (label_191 / label_192 / label_193)
Handler do ícone remédio (n=4). Entrada pelo menu; saída `label_160`.
```c
if (M(0x04A) & 8) goto back_to_menu;          // 0x600: pet morto -> nada      (0x04A bit3 = morto, ver RAM)
if (!(M(0x048) & 8)) goto refuse_anim;         // 0x602: não doente -> recusa (label_194)
// label_192 (0x606): doente
M(0x048) &= 7;
anim_play(A=8, B=5, Y=3);                      // call label_273 (0x8A9)  animação "remédio"/careta
M(0x048) = ((M(0x048) | 8) + M(0x23B)) & 0xF;  // 0x610-0x612   (M(0x23B) = "força do remédio" por estágio, bebê = 0xC)
if (M(0x048) & 8) goto back_to_menu;           // ainda doente (precisa de mais doses)
// curado (bit3 limpo):
copy3(0x20D <- 0x238);                          // recarrega contador de 3 nibbles 0x20D-0x20F (com 0x07D desligado)
back_to_menu: pset 5; jp label_160
```
`0x048`: bit3=doente, bits0-2 acumulam doses (?). Efeito: duas doses curam quando 0x048 foi posto em 0xF (visto: 0x048 vira F aos
~2573 s). Observado em teste: pet saudável -> só 0x600-0x605,0x61E-0x623 executam (recusa).
Sub-rotinas:
* `0x61E–0x621` `refuse_anim` (label_194): `A=6,B=5; call label_272 (0x8A8, Y=0)` = animação "balança a cabeça"; segue p/ `0x622 label_195` (`pset 5; jp label_160`).
* `0x61C–0x61D` (label_193): `back_to_menu`.
Chamadores: só a tabela 0x700 (0x708) e `jp` internos de 0x624-0x62C (label_194/195).

## 0x624–0x6C7 `play_guess_game` (label_196 / label_197 … label_207)
Jogo "para onde o bichinho vai virar?" (ícone jogo, n=3). 5 rodadas; L = esquerda, M = direita; R = sair. 3+ vitórias ⇒ +1 coração de felicidade.
O resultado de cada rodada é **sorteado** (não depende do palpite!): o palpite só decide *para que lado* o bicho é desenhado virando.
```c
// 0x624 label_196
if (M(0x04A)&8) goto back_to_menu;                   // morto
label_197:                                           // 0x626 (também reentrada p/ "jogar de novo")
if (M(0x048)&8) goto refuse_anim;                    // doente
if (M(0x209) != 0) goto refuse_anim;                 // flag "malcriado/precisa disciplina" (?) ver RAM
M(0x05E)=5; anim_select();                           // label_142 (pg4): seleciona animação 5 (pet esperando)
clear_page_0x100(); anim_step(); copy_buf_and_render_misc();   // label_145 (pg4) / 0x400
tilelist[0x90..0x97] = {FF,1C,FF,1C,1D,FF,1D,FF};    // 0x637-0x63F: corações cheios/vazios (tiles 0x1C/0x1D)
sound(0xD6);                                         // if M(0x07B) (som ligado) -> buzzer
render_tile_list();  copy_video_buf_to_vram();       // label_34 (0x5DE) + 0x556
wait(0x0D ticks);                                    // copy_xhl_to_0x022_or_loop_0x023, X=0x0D
slide(B=0xC);                                        // label_156 (0x500): rola o buffer de vídeo (M(0x2A:0x2B) += B) até estourar
M(0x82)=5;  M(0x83)=0;                               // rodadas restantes, vitórias   (0x649-0x64B; ldpx)
do {                                                 // label_198 (0x64C)  --- uma rodada ---
    M(0x81)=0;                                       // palpite do jogador (0=ainda não)
    M(0x80)=M(0x246);  M(0x84)=8;                    // 0x246 = nº de quadros de espera (stage; bebê=1)
    if (rng_carry(M(0x245)))   { /* ganha: mantém */ }          // label_282 (0x900): C = (M(0x05A)+A+1 > 15), A=M(0x245)
    else { M(0x80)=M(0x247); M(0x84)=0; }            // perde: 0x84=0
    // M(0x84)!=0 <=> rodada vencida. P(vitória)=M(0x245)/16 (bebê: 8/16)  (M(0x05A)= contador livre incrementado na ISR 0x182)
    M(0x5E)=5; anim_select(); M(0x26..0x29)->buttons;
    M(0x57)=0xF (timeout)  -- 0x665-0x666
    for(;;){                                         // label_200 (0x667)
        sound_cmd(0x97);                              // 0x667-0x668 (se som ligado)
        clear_page_0x100(); anim_step(); draw_guess_arrow(); copy_buf_and_render_misc(); buttons=read();
        if (buttons & 1 /*R*/ || M(0x57)==0) goto exit_game;     // label_207
        if (M(0x81)==0) { if(!(buttons&6)) continue; M(0x81)=buttons; }   // palpite: 2=M(direita) 4=L(esquerda)
        if (--M(0x80) != 0) continue;                // espera M(0x80) quadros após o palpite (label_201)
        break;
    }
    // resolução (0x67D-0x695)
    sound(0x94);  clear_page_0x100();
    B = M(0x84); if (M(0x81)&4 /*L*/) B ^= 8;        // direção desenhada = resultado XOR palpite
    M(0x3A)=0,M(0x3B)=1;  draw_turn(A=?,B);          // call label_128 (0x4EE, pg3)
    draw_guess_arrow(); copy_buf_and_render_misc(); wait(0x29 ticks);
    if (M(0x84)==0) lose_feedback(); else { M(0x83)++; win_feedback(); }
} while (--M(0x82) != 0);                            // label_204 (0x697)
// tela de resultado (0x69B-0x6B4)
tilelist = label_334 template {18,FF,1D,FF,00,0F,00,FF}; M(0x98)=wins; M(0x9C)=5-wins;   // face / ♡ / "wins ? losses" (dígitos = tiles 0..9)
sound(0xE5); render_tile_list(); copy_video_buf_to_vram(); wait(0x52);
if (wins < 3) lose_feedback();                       // label_205
else { M(0x41)=min(M(0x41)+4,0xF); win_feedback(); } // label_331 (0xCE5): +1 coração de felicidade (4 nibbles = 1 coração)
// label_206 (0x6B6)
weight -= 1  (BCD, flag D):  M(0x46)+=9; M(0x47)+=9+C;  clamp_weight();   // 0x99 BCD = -1 mod 100
if (M(0x29) & 1 /*R*/) goto exit_game;
if (event_check() == Z) goto label_197;              // call label_357 (pg F): sem evento pendente -> joga outra partida
exit_game: sound(0x94); pset 5; jp label_159          // label_207 (0x6C5) (deseleciona menu)
```
Confirmado no emulador: `M(0x82)` 5→4→…, `M(0x81)` = 4 ao apertar L, `M(0x84)` 8→0 (perdeu), `M(0x83)` 0→1 numa vitória; peso (5, mín=máx do bebê) volta a 5 pelo clamp.

Funções auxiliares (todas só chamadas por este jogo):
* `0x6C8–0x6CC` `win_feedback` (label_208): sound `Y=0x83`; `A=7, Y=6` → `jp label_210`.
* `0x6CD–0x6D0` `lose_feedback` (label_209): sound `Y=0x9E`; `A=8, Y=3` → label_210.
* `0x6D1–0x6D3` label_210: `B=5; pset 8; jp label_273` (0x8A9) = `play_pet_animation(A=anim id, B=5 (tempo?), Y=variante)`.
  Animações vistas: A=2 comer, A=6 recusar (chacoalhar), A=7 feliz, A=8 triste/ai (também disciplina, remédio).
* `0x6D4–0x6E4` `draw_guess_arrow` (label_211): se `M(0x81)!=0`: tile `0x26` (seta ◄, L) em buffer 0x180 ou `0x27` (►, M) em 0x1B0 via `misc_render(B=2)`; senão nada.
* `0x6E5–0x6F5` `clamp_weight` (label_214): peso `V=[0x47:0x46]` (2 dígitos BCD) clamp em `[min,max]` onde `min=[0x23D:0x23C]`, `max=[0x23F:0x23E]` (tabela do estágio; bebê 05/05):
  ```c
  if (V < min) V = min; else if (V >= max) V = max;   // (V==max grava max, igual)
  ```
  (usa `clear_0x07D`/`set_f_0x07D` em volta da cópia). Chamadores: 0x6BE, 0x760 (`jp` de `add_weight`), 0xDFF (`jp`, fora da faixa).
* `0x6F6–0x6FD` `cmp_weight_bound` (label_218): compara `V` (0x46/0x47) com o par apontado por Y (`my`); retorna C/Z como `cp` de 2 dígitos (compara dígito alto; se igual, dígito baixo em `Y-1`).
* 0x6FE–0x6FF: `nop7`.

Dados do jogo (RAM do estágio, copiados de tabela pelo código de evolução, fora da faixa): `M(0x245)`=chance de vitória/16 (bebê 8), `M(0x246/0x247)`=quadros de espera após palpite (bebê 1/1), `M(0x248) bit0` (variante de animação ao comer, ver food).

## 0x710–0x755 `food_menu` (label_220 / 221 / 223 … 229)
Ícone comida (n=1). Menu de 2 itens ("refeição" / "lanche"), pode alimentar várias vezes até R/timeout.
```c
if (M(0x04A)&8) goto back_to_menu;                    // morto  (label_222 -> label_160)
for(;;){                                              // label_221 (0x712)
    M(0x78) = M(0x73);                                // cursor inicial = última escolha
    tilelist[0x90..0x97] = {FF,28,29,2A,FF,2B,2C,2D}; // label_308 (0xBE8, pg B): dois rótulos de 3 tiles (0x28-0x2A "refeição", 0x2B-0x2D "lanche"; kana?)
    r = two_item_menu(timeout=0xA);                   // call label_352 (0xE5A, pg E): C=1 cancelou/timeout, senão A=0|1
    if (C) { if (Z==0) goto idle /*label_159*/; else goto back_to_menu /*label_160*/; }  // R: volta ao menu; timeout/evento: ocioso
    M(0x73) = A;                                      // label_223 (0x722) memoriza escolha
    if (A == 0) {                                     // REFEIÇÃO
        Y = 0xC;
        if ((M(0x048)&8) || M(0x209) != 0 || M(0x040) == 0xF) { anim_play(A=6,B=5,Y=0xC); continue; }   // recusa (label_228)
        M(0x040) = min(M(0x040) + 4, 0xF);            // label_331: +1 coração de fome
        add_weight(1);                                // label_230
        Y = 8;
    } else {                                          // LANCHE
        M(0x041) = min(M(0x041) + 4, 0xF);            // +1 coração de felicidade
        if (!(M(0x048)&8)) { dec3(0x20D..0x20F) saturando em 0 (label_324, pg C, com 0x07D desligado); }   // (?) contador de 3 dígitos
        add_weight(2);
        Y = 0xA;
    }
    if (M(0x248) & 1) Y++;                            // 0x749-0x74E variante da animação
    anim_play(A=2, B=5, Y);                           // comer
}
```
Verificado: refeição `M(0x040) 0→4`, lanche `M(0x073)=1`, `M(0x041) 0→4`, `M(0x20D) 6→5`, `M(0x05E)=2`.
Notas: `M(0x78)` = cursor inicial passado a `two_item_menu`; `M(0x73)` memória da última escolha (0=refeição,1=lanche).
Chamadores: 0x702 (tabela). Chama: `label_308` (0xBE8), `label_352` (0xE5A), `label_331` (0xCE5), `label_324` (0xCC8), `label_273` (0x8A9), `label_230`.

### 0x756–0x760 `add_weight` (label_230)
`A` = gramas/onças a somar (1 refeição, 2 lanche). Em modo decimal (D): `V=[0x47:0x46]; V += A; if (V > 99) V = 99;` e `jp label_214` (clamp). Retorna ao chamador de `label_214`. Chamadores: 0x736, 0x747.
```c
V = BCD([0x47:0x46]) + A;   // flag D ligada: add mx,a ; adc mx,0
if (carry) V = 0x99;       // satura em 99
clamp_weight();            // jp label_214
```

| 0x054,0x055 | 0,0 | (?) |
| 0x048..0x051 | 0,0,0,F,0,0,0,0,0,0 | 0x048 doente/doses=0, 0x049=0, 0x04A morto=0, **0x04B=F (luz acesa)**, 0x04C-0x051=0 |

## 0x792–0x7BF Renderizador de tiles 8x8
### 0x792–0x7A2 `render_tile_list` (label_233)
Desenha **8 tiles** (tela inteira de texto 4+4) a partir da lista em `M(0x090..0x09F)`: cada tile = 2 nibbles (A=lo, B=hi) ⇒ id = `B*16+A`.
Destino: `X = {XP=1, XH=M(0x3B), XL=M(0x3A)}` (ponteiro no buffer de vídeo 0x100–0x1FF; `label_30`/`label_34` põem 0x3A:0x3B=0x40 ⇒ 0x140). Depois de 4 tiles faz `X += 0x40` (`adc xh,4`) para a 2ª faixa.
Chamadores: `label_34` (0x5DE, via `jp`), 0xE72 (menu de 2 itens), 0x0E1. Usa `XL/XH` como ponteiro vivo; `Y` varre 0x090.

### 0x7A3–0x7A4 `fetch_and_misc_render`: `A=M(Y++); B=M(Y++)` e cai em `misc_render`.
### 0x7A5–0x7B7 `misc_render(A,B,X)`  (label do agg23: `misc_render`)
Desenha o tile `n=B*16+A` (`n<0x40`) em 16 nibbles a partir de `M(X)` (X avança 16). `n>=0x40` (B≥4, ex. FF) ⇒ `clear_16_addrs` (apaga 16 nibbles).
Implementação: `m0=(A&1)*8; m1=(n>>1)&0xF; m2=6+(n>>5)`; `pset 0; jp render_asset (0x000)` que faz `jpba` para a tabela de gráficos de 0x1000.
**Dados do tile**: ROM `0x1600 + 8*n` (64 tiles, 0x1600–0x17FF), 8 palavras `lbpx` ⇒ 8 colunas × (nibble baixo = linhas 0–3, nibble alto = linhas 4–7). Verificado: tile 0x00..0x09 dígitos, 0x0F ?, 0x18 rosto, 0x1C coração cheio, 0x1D coração vazio, 0x26 ◄, 0x27 ► (também cursor do menu), 0x28–0x2D rótulos de menu.
Retorna pelo `retd` final do tile (a chamada é `jp`, então o retorno é para o chamador de `misc_render`).
Chamadores (dentro de 0x600–0x7FF): 0x6E3 (`draw_guess_arrow`), 0x79A–0x7A2 (render_tile_list); fora: 0x3D1,0x419,0x428,0x431,0x45E,0x55C,0x560,0x5C5 e `label_233`.
### 0x7B8–0x7BF `clear_16_addrs` / `clear_8_addrs_ret`
`clear_16_addrs`: 4×`lbpx 0` + cai em `clear_8_addrs_ret` (3×`lbpx 0` + `retd 0`) ⇒ zera 16 (ou 8 se entrar em 0x7BC) nibbles a partir de `M(X)` e retorna. Chamadores: `misc_render` (jp nc), 0x5C7 (call 0x4B8), 0x5CE (call 0x4BC).

## 0x7C0–0x7D4 `set_menu_icon` (label_238; entrada `springboard_label_238` = 0x5ED, e `label_38` = 0x5EC com A=0)
Entrada: `A` = ícone destacado (0 = nenhum, 1..8 = ícone 0..7). Escreve em `M(0x02C)`,`M(0x02D)` a máscara de 8 bits (nibble baixo, alto) via tabela 0x7D8, depois liga o ícone "atenção" (bit 7 = `M(0x02D)|=8`) e chama a parte que escreve no LCD.
```c
mask = (A==0) ? 0 : 1 << (A-1);   // tabela 0x7D8, lida por label_241 (jpba em 0x7D5: B:A = A+0x8 + 0xD00 -> 0x7D8+A)
M(0x02C)=mask & 0xF; M(0x02D)=mask >> 4;
if (!(M(0x04A)&8)) { if (M(0x208) || M(0x209)) M(0x02D) |= 8; }     // vivo: atenção acesa se há chamado (fome/felicidade/doença = 0x208) ou disciplina (0x209)
else               { if (M(0x205) < 4)          M(0x02D) |= 8; }     // morto: atenção acesa enquanto 0x205<4 (?)
write_icons();   // falls to label_242
```
Chamadores: `label_88` (0x294, A=0), 0x527/0x53E/0x555 (menu), `label_38` (0x374, 0x509, 0x983).
### 0x7D5–0x7D7 `icon_mask_lookup` (label_241) e tabela 0x7D8–0x7E0
`add a,8; adc b,0xD; jpba` ⇒ salta para `0x7D8+A` (A=0..8); cada `retd` grava (lo,hi) em `M(X),M(X+1)` e retorna:
| A | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| retd | 0x00 | 0x01 | 0x02 | 0x04 | 0x08 | 0x10 | 0x20 | 0x40 | 0x80 |
(valor = máscara de ícone; lo nibble → `M(0x02C)`, hi → `M(0x02D)`.)
### 0x7E1–0x7FE `write_icons` (label_242)
Lê `A=M(0x02C)`, `B=M(0x02D)` e escreve nos nibbles de segmento do LCD (XP=E): `M(0xE10)=A` (ícones 0–3 = seg 8 com 0–3), `M(0xEB9)=B` (ícones 4–7 = seg 28 com 12–15) e cópias rotacionadas (`rrc a`/`rlc b`) em `0xE22,0xE24,0xE26` e `0xECB,0xECD,0xECF` (segmentos duplicados do mesmo ícone, ver comentário `IC n -> ...` em `tamalib/hw.c`). (Atenção: `ld x,0x10` com XP=E é o endereço **0xE10**, não a RAM 0x010.)
Chamadores: `label_83` (0x279, `call 0x4E1`) e `label_238`. 0x7FF: `nop7`.
