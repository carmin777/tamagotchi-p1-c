# ROM 0x800–0x9FF (página 8 e 9)

Fonte: `tools/asm.py 0x800 0x9FF` + cpu.c. Verificação dinâmica com `harness/trace` (estado salvo = bebê vivo, idade 0).
Convenções: `Mxxx` = nibble de RAM; `mN` = RAM[0x00N] (registradores de rascunho da página 0, `ld m0,a`).
`B:A` = byte com B no nibble alto (usado por `jpba`). Bytes em RAM são little-endian por nibble
(`lbpx mx,0xNN` / `retd 0xNN` grava M(X)=NN&F, M(X+1)=NN>>4 e X+=2; `lbpx` segue adiante, `retd` também retorna).
Botões (M026/M028 = estado; M027/M029 = latch de "apertado desde a última leitura"): bit0=R, bit1=M, bit2=L
(confirmado: M avança a página do status; `copy_0x026_7_to_8_9` devolve A=M026, B=M027 antigos).

Resumo do que a faixa é: (1) tela de **Status** (ícone 6), (2) **player de animações-overlay** (`play_overlay_anim`, ícones tipo
comida/Z/caveira/estrelas por cima do bichinho), (3) efeito de **dissolve para preto**, (4) **desenho do sprite do bichinho** (2 tiles 16x8, com espelhamento),
(5) espera de boot (ovo), (6) tabelas de **scripts de posição X do bichinho**.

Tamanho de tiles de gráfico (confirmado com "Useful Addresses.md"): sprites do bichinho = 16 words (0x1000+16*id, id 3 = 0x1030);
glifos "misc" (dígitos, textos, ícones) = 8 words (0x1600+8*id, id 0..9 = dígitos grandes, 0x18 bebê, 0x19 "yr", 0x1A balança, 0x1B "OZ",
0x1C coração cheio, 0x1D vazio, 0x2E-0x30 "Hungry", 0x31-0x33 "Happy", 0x34-0x37 "Discipline", 0x10-0x13 pão (inteiro/1ª mordida/2ª/vazio),
0x14-0x16 lanche, 0x1E/0x1F fedor de cocô, 0x20/0x21 Z, 0x22 caveira, 0x23 brilho de sucesso, 0x24/0x25 raiva).
Buffer de vídeo = RAM 0x100–0x1FF (página 1); `copy_video_buf_to_vram` (0x556) copia de {1,M02B,M02A} (M02A:B = 0x40 → 0x140) para o LCD.
Metade "de cima" do buffer = 0x140–0x17F (4 tiles de 16 nibbles = 8 colunas cada), "de baixo" = 0x1C0–0x1FF (+0x80).

## 0x800–0x807  `dither_masks`  (agg23: "Jump table for choose_x_word_244")
Tabela de 8 `retd`: índice 0..7 → byte 0x20, 0x08, 0x01, 0x40, 0x02, 0x80, 0x10, 0x04 (permutação dos 8 bits; ordem de preenchimento do dissolve).
Lida por `dither_mask_lookup`. Dado de lógica (efeito visual), não gráfico.

## 0x808–0x80C  `dither_mask_lookup`  (agg23: `choose_x_word_244` + `jp_a`)
Entrada: A = índice (precisa de `pset 8` do chamador); X = destino. Saída: M(X)=byte&F, M(X+1)=byte>>4 (X+=2).
```c
void dither_mask_lookup(u4 a) { if (a & 8) { M[x]=0; M[x+1]=0; } else { /*jpba 0x800+a*/ M[x..x+1] = dither_masks[a]; } }
```
Chamador: `or_dither_pattern` (0x917). Nada além.

## 0x80D–0x813  `clear_quads_p1`  (agg23: `label_245`/`label_246`)
Seta XP=1; apaga `4*A` nibbles a partir de X (A=0 → 16 iterações = 64 nibbles). Entrada: A, X (8 bits baixos). `ret`.
```c
void clear_quads_p1(u4 a, u8 x) { u4 n = a ? a : 16; do { RAM[0x100+x..+3] = 0; x += 4; } while (--n); }
```
Chamadores: `label_155` (0x4EA, 0x4EE, 0x4F7: limpa 0x140.., 0x1C0.., 0x170.. ao montar a tela do relógio/ícone 0).

## 0x814–0x835  `status_screen`  (agg23: `label_247`..`label_252`)
Rotina do **ícone Status (6º)**: despachada pela tabela 0x700 (entrada idx 6: `pset 8; jp label_247` em 0x70C/0x70D), confirmada rodando o harness (L×6, M).
Mostra 4 páginas em ciclo; M ou R avançam; L sai; sai sozinha após 15 s (M057 = 0xF, decrementado a 1 Hz pelo `clock_timer_int`)
ou se `label_357` (0xF00, verificador de eventos; retorna Z = nada pendente) acusar evento (M05C != 0).
RAM: M080 = página (0..3). M081 = flag "desenhar moldura do gauge" (zerada por `status_build_page`). M057 = timeout (s).
```c
void status_screen(void) {            // 0x814
    M[0x80] = 0;
    for (;;) {                        // label_248
        status_build_page();          // 0x836: preenche tabela de 8 ids em M090..M09F e M081
        label_34();                   // 0x5DE: M02A:B = 0x40 (origem do buffer), M03A:B = 0x40; chama label_233 (0x792) -> desenha os 8 glifos
        if (M[0x81] != 0) draw_discipline_gauge();     // 0x867
        copy_video_buf_to_vram();     // 0x556
        read_buttons();               // 0x521
        M[0x57] = 15;                 // timeout em segundos
        for (;;) {                    // label_250
            read_buttons();           // A=M026 antigo, B=M027 antigo (latch)
            if (M[0x57] == 0 || (B & 1)) goto exit;      // timeout ou L
            if (!(B & 6)) continue;                       // espera M ou R
            beep(0x94);               // 0x5BB: if M07B: M032=0; M036:37=0x94; M058=A; M059=F
            M[0x80] = (M[0x80] + 1 < 4) ? M[0x80] + 1 : 0;
            if (event_check_0xF00()) goto exit;           // pset F; call 0xF00; jp z,label_248
            break;                    // volta a reconstruir a página
        }
    }
exit:
    beep(0x94); goto main_idle_label_160;                 // pset 5; jp 0x51A (0x835)
}
```
Observação: o `read_buttons` zera M027; B fica com o valor lido.

## 0x836–0x842  `status_build_page`  (agg23: `label_253`)
XP=0, YP=0; A=M080; M081=0; calcula B:A = (page-1)+0x30 (page 0 → 0x3F; 1→0x40; 2→0x41; 3→0x42) e `jpba` na própria página 8
→ tabela de 4 `jp` em 0x83F..0x842: página 0→`label_254`, 1→`label_257`, 2→`label_264`, 3→`label_265`. X=0x90 na entrada.
Cada subrotina preenche **8 ids de glifo (1 byte/id, 2 nibbles, em M090..M09F)**; `label_233` (0x792) desenha 4 no topo (X=0x140+16*i)
e 4 embaixo (+0x80). Byte id: nibble baixo = id&F, nibble alto = id>>4; alto >=4 (p.ex. 0xF) = tile em branco (`clear_16_addrs`).

### 0x843–0x85B  `status_page_age_weight`  (`label_254`..`label_256`)  — página 0


### 0x85C–0x866  `status_page_discipline`  (`label_257`) — página 1

### 0x867–0x882  `draw_discipline_gauge`  (`label_258`, `label_260`..`label_263`; sub `label_261`/0x87D)
Desenha a moldura do gauge no buffer 0x1C2..0x1FF e preenche M043−1 segmentos.
```c
XP=1;
RAM[1C2..1C3]=0x3D; fill14(0x1C4, 0x42); RAM[1E0..1E1]=0x43; fill14(0x1E2,0x42); RAM[1FE..1FF]=0x3D;  // fill14 = 14 words 0x42 (nibbles 2,4)
n = M[0x43] ? M[0x43] : 1;
for (i = 1; i < n; i++) { RAM[0x1C6 + 4*(i-1)] = 0x5A /*nibbles A,5*/; }   // 14 segmentos máx.
```
=> **M043 = disciplina (0..F)** (segmentos = M043−1). Geometria exata dos pixels (?).

### 0x883–0x888  `status_page_hunger` (`label_264`) — página 2
Ids {0x2E,0x2F,0x30 ("Hungry"), 0xFF}; Y=0x40; cai em `draw_hearts`.
### 0x889–0x88B  `status_page_happy` (`label_265`) — página 3
`pset B; call 0xBF8` (grava {0x31,0x32,0x33 ("Happy"),0xFF} em M090..097); Y=0x41; cai em `draw_hearts`.
### 0x88C–0x89D  `draw_hearts`  (`label_266`..`label_270`)
Entrada: Y → valor v (M040 hunger, M041 happy), X no 5º id. Grava 4 ids: 0x1C (cheio)/0x1D (vazio).
```c
n = (v >= 0xF) ? 4 : ((v + 1) >> 2) & 3;      // v 0-2→0, 3-6→1, 7-10→2, 11-14→3, F→4 corações
for (i=0;i<4;i++) { *ids++ = (n==0) ? 0x1D : 0x1C; if (n) n--; }
```
=> **M040 = fome (hunger), M041 = felicidade (happy)** (validado: M040=4 → 1 coração cheio; M041=0 → 0).

## 0x89E–0x8FF  Player de animação-overlay
Entradas (todas terminam em `label_274`/loop `label_275`):
- `play_overlay_anim_autostate` (`label_271`, 0x89E): Y=0 (script 0); chama `label_176` (0x596) que escolhe M05E (1 normal, 9 se bit alto de M048, 3 se bit alto de M04A) e reinicia a animação do bichinho se mudou. Chamadores: 0x351, 0x371 (evolução, `label_112`).
- `play_overlay_anim_y0` (`label_272`, 0x8A8): Y=0, cai em `label_273`. Chamadores: 0x621, 0xFF5.
- `play_overlay_anim` (`label_273`, 0x8A9): **A = estado da animação do bichinho (→ M05E), B = tempo máximo em s (→ M057), Y(yh:yl) = índice do script de overlay (0..0xC)**.
  Chamadores: 0x60B, 0x6D3, 0x754, 0xAED, 0xD91, 0x3D6 (`label_124`), etc.
  (A,Y) vistos: (8,3) recusa/raiva, (7,6) feliz/sucesso, (2,0xA/0xB) comendo lanche, (6,..) etc. (nomes semânticos ?).

```c
void play_overlay_anim(u4 a, u4 b, u8 y) {            // 0x8A9
    M[0x5E] = a;  /*xp=0*/            // (271 recalcula via label_176)
    M[0x57] = b;                        // timeout em segundos (decrementado a 1 Hz)
    {M[0xA6],M[0xA7]} = overlay_script_index[y];       // jp_table_0xE00 em 0xE00: ponteiro (byte) p/ script em 0xE0E..0xE59
    M[0xAA] = 0;
    pet_anim_init();                    // 0x465 (label_142): zera M05F, M066/67; escolhe scripts por (M05D,M05E)
    read_buttons();
    for (;;) {                          // label_275 (0x8B9)
        clear_page_0x100();             // 0x540
        pet_anim_tick();                // 0x486 (label_145): avança scripts de caminho/posição e desenha o bichinho
        if (M[0xAA]-- == 0) {           // add mx,0xF; carry<=>M[AA]!=0
            p = M[0xA6] | M[0xA7]<<4;  M[0xA6..A7] += 2;       // 8 bits
            fetch step bytes: w0 -> M[A2:A3], w1 -> M[A4:A5], [w2 -> M[A6:A7] (novo ponteiro = loop)]   // jp_table_0xE00(p)
            M[0xA8] = w0 & 0xF;  M[0xA9] = (w0 >> 4) & 3;       // id do glifo = w0 & 0x3F
            M[0xAA] = (w0 >> 6) & 3;                             // passo dura M[AA]+1 iterações
        }
        if (!(M[0xA8]==0xF && M[0xA9]==3)) {                    // id 0x3F = não desenhar
            x = w1;                                              // posição = endereço no buffer p1 (xh:xl = w1)
            if (M[0x5D] == 1) {                                  // (estágio 1 = bebê, ver nota) remapeia
                xh = xh ? (xh|8) : 0;  c = (xl+8)>15; xl=(xl+8)&15;
                s = xh + 0xF + c; xh = s & 15;
                if ((xh|8) == 0xF) xh = (xh+1)&15;
            }
            misc_render(id = M[A8] | M[A9]<<4, X = 0x100|xh<<4|xl);   // fetch_and_misc_render 0x7A3
        }
        copy_buf_and_render_misc(); copy_video_buf_to_vram();   // 0x554
        read_buttons();                 // A,B = M026/27 antigos
        if (M[0x57] == 0) return;       // tempo esgotado (também: B==0 → só 1 quadro)
        if (M[0x74] == 0) continue;     // M074 != 0 => permitir cancelar por botão (?)
        if ((B & 7) == 0) continue;
        beep(0x94);  return;            // 0x8FE
    }
}
```
Notas:
- O laço não tem espera explícita: o ritmo vem da lentidão da CPU (cada iteração: clear 256 nibbles + draw ≈ centenas de ms; medido: 14 iterações em alguns s). Durações dos scripts estão em **iterações**, não em segundos.
- Efeito do remapeamento M05D==1 (confirmado M05D=1 no estado "bebê"): X' = X+8 nibbles e, se xh≠0, desloca para o outro banco (+0x78 efetivo; xh=0 fica em xh=0). Intenção: reposicionar overlays para o bichinho pequeno (?).
- M074: escrito em 0x378 (=0), 0xFF8 (=F), 0x1213 (=0); semântica "botão cancela" é hipótese (?).
- Formato dos scripts de overlay (0xE0E..0xE59, fora da faixa; tabela de índice em 0xE00): cada passo = 2 bytes `[w0][w1]`, opcional 3º byte = novo ponteiro (low byte, página E) → loop. Chain = `lbpx`.. `retd` (o `retd` encerra). Decodificado:

| idx | ptr | passos (w0 w1) → (glifo, rep, posição) | uso |
|---|---|---|---|
| 0 | 0xE0E | FF 50 loop E0E | vazio |
| 1 | 0xE11 | 60 30 / 61 30 loop E11 → glifos 0x20/0x21 (Z) em 0x130 | dormindo |
| 2 | 0xE16 | FF50, FF50, 5E A8 / 5F A8 loop E1A → 0x1E/0x1F em 0x1A8 | cocô fedido |
| 3 | 0xE1F | 65 30 / 64 30 loop E1F → 0x25/0x24 em 0x130 | raiva |
| 4,5 | 0xE24 | 62 30 / 7F 50 loop E24 → 0x22 caveira pisca | doente |
| 6 | 0xE29 | 7F 50 / 63 30 loop E29 → 0x23 brilho pisca | sucesso |
| 7 | 0xE2E | D7 B0 loop → 0x17 fixo em 0x1B0 | (?) |
| 8 | 0xE31 | 10 00, 10 80, D1 80, D2 80, D3 80 loop → pão: inteiro, 1ª, 2ª mordida, vazio | comer pão |
| 9 | 0xE3C | 10 00, 10 80, 52 80, 53 80 loop | pão (curto) |
| 10 | 0xE45 | 14 00, 14 80, D5 80, D6 80 → jump E0E | lanche |
| 11 | 0xE4E | 14 00, 14 80, 56 80 → jump E0E | lanche (curto) |
| 12 | 0xE55 | 10 00, D0 80 loop E57 | pão parado |
(w0: bits0-5 glifo, bits6-7 repetições extras; w1: endereço no buffer p1.)

## 0x900–0x905  `rand_chance`  (agg23: `label_282`)
```c
bool rand_chance(u4 a) { if (a == 0) return 0 /*C=0*/; M[0x5A] = M[0x5A] + a + 1; return carry; }
```
M05A é um contador livre incrementado a cada tick do prog timer (256 Hz) em `prog_timer_int` (0x181) → fonte de aleatoriedade; P(carry)≈(a+1)/16, e avança a "semente". Chamador: 0x659 (`label_198`, rotina do ícone 3, A=M245).

## 0x906–0x912  `screen_dissolve`  (agg23: `copy_video_buf_8x`, via `jp_copy_video_buf_8x` 0x3FC)
Dissolve em 8 passos: a cada passo OR de uma máscara em toda a página 0x100, copia ao LCD, espera 1 tick de prog timer; no fim limpa o buffer.
```c
void screen_dissolve(void) {      // m2 = passo, m3 = restantes (8)
    for (m2=0, m3=8; m3; m2++, m3--) { or_dither_pattern(m2); copy_video_buf_to_vram(); delay_ticks(0x01); /* copy_xhl_to_0x022_or_loop_0x023, X=1 */ }
    clear_page_0x100();
}
```
Chamadores: 0x34E, 0x352 (evolução `label_112`), 0x375 (morte `label_116`). Efeito colateral: m2=8, m3=0.

## 0x913–0x927  `or_dither_pattern`  (agg23: `or_0x100_ab`)
Entrada: m2 = passo (0..7). `dither_mask_lookup(m2)` → M000=lo, M001=hi do byte; depois, para os 256 nibbles de 0x100–0x1FF:
`buf[4k]|=lo; buf[4k+1]|=lo; buf[4k+2]|=hi; buf[4k+3]|=hi`. Acumulando os 8 passos todos os nibbles viram 0xF (tela preta).

## 0x928–0x97E  Desenho do sprite do bichinho (2 tiles 16x8 empilhados)
Chamadores: `pet_anim_tick` (0x4CA → 0x928, 0x4E1 → 0x939), `label_128/127` (0x3F4/0x3FB: telas de morte/fantasma, desenham par A=parte,B=flip).
- `draw_pet_upper` (`label_288`, 0x928) **A = índice da parte (nibble), B = flags (bit3 = espelhar)**; `draw_pet_lower` (`label_289`, 0x939): idem usando a tabela 0xD00 (a metade de baixo vai em X+0x80: quem chama soma 8 a M03B antes).
```c
// label_288; label_289 idêntico trocando 0xC00 por 0xD00
m0 = a; m3 = b;
{m1,m2} = table_0xC00[ M[0x5D] ];            // ponteiro (byte) por estágio (jp_table_0xC00; entrada 0xC00+estágio)
{M[0x24],M[0x25]} = table_0xC00[ (m2<<4|m1) + m0 ];   // byte = id do tile; indexa o 2º nível (offset+parte)
M[0x25] ^= (m3 & 8);                           // bit3 de M025 = flag de espelhamento
render_pet_tile();                             // label_291
```
- `render_pet_tile` (`label_290`/`label_291`, 0x949–0x97E):
```c
id = ((M[0x25] & 7) << 4 | M[0x24]) + 3;   if (id >= 0x80) return;   // m2:m1 = id; m0 = 0
render_asset(id, X = 0x100 | M[0x3B]<<4 | M[0x3A]);   // 0x500 (calz): tile em 0x1000 + 16*id para o buffer p1
if (M[0x25] & 8) {                          // espelha horizontalmente (16 colunas de 2 nibbles)
    X = M3A:3B;  Y = X + 0x1E;
    for (i = 0; i < 8; i++) { swap(M[X],M[Y]); swap(M[X+1],M[Y+1]); X += 2; Y -= 2; }
}
```
M03A:M03B = posição X do sprite (endereço no buffer p1).

## 0x97F–0x98A  `boot_wait_for_start`  (agg23: `label_294`, `loop_294`)
Tela de espera inicial (ovo): chama `label_232` (0x761: inicializa estado de jogo: M05D=0, M05E=1, M040/M041=1, M046=5, M054/55=0, M048..=..., M015=5, M016/17=0x28 etc.), `pet_anim_init`, `label_38`,
e entra em laço: `clear_page_0x100(); pet_anim_tick()+draw (label_13 0x552); read_buttons();` até M029 bit1 (M) → `pset 5; jp label_167` (0x553: tela de acerto do relógio).
Chamadores: 0x241/0x26A (pós-reset), 0x58C.

## 0x98B–0x99A  `pos_script_index`  (tabela de 16 retd; usada por `pet_anim_init`, 0x47A)
`pet_anim_init` calcula `B:A = M1 + 0x8B` com M1 = nibble alto do byte da tabela 0xB00 (por M05D:M05E) e salta (`pset 9; jpba`) para 0x900+B:A ⇒ ponteiro low-byte para o script:
idx → ponteiro: 0→9B, 1→9E, 2→B1, 3→BE, 4→C3, 5→CE, 6→D3, 7→DC, 8→E5, 9→EC, 10→F1, 11..15→00 (não usados).
O `retd` grava o ponteiro em M06A:M06B.

## 0x99B–0x9FF  `pos_scripts`  (scripts de posição/espelhamento do bichinho)
Lidos por `pet_anim_tick` (0x496–0x4E0) — fora da faixa mas formato fechado aqui. Cada passo = 2 bytes, opcional 3º = ponteiro de loop (byte low em página 9):
```c
// por tick: if (--M[0x66:0x67] borrow) { p = M06A:6B; M06A:6B += 2; step = jp_table_0x980_2(p) -> M066:067 = w0, M068:069 = w1, [M06A:6B = w2]; M070 = M067; M067 = 0; }
// w0: nibble baixo (M066) = duração-1 em ticks de animação; nibble alto -> M070 = flags
//   M070 bit3: desenhar tile de cima; bit2: desenhar tile de baixo; bit1: espelhar cima (xor M063.bit3); bit0: espelhar baixo (xor M063.bit2)
//   (M063 vem do script de caminho 0xB00: bit1/bit0 escolhem M06F em vez de M06E como parte de cima/baixo)
// w1: posição X do sprite (M06C:6D -> M03A:3B). bit0==0: valor absoluto; bit0==1: relativo, delta = (w1 & 0xFE) (8 bits, p.ex. 0xFB = −6, 0x07 = +6)
```
Verificação dinâmica (estado bebê): M06A:6B=0xB7, M068:69=0x0C, M066:67=0, M070=F, M06C:6D=0x0C ⇒ último passo lido = (F0,0C) do script 2.
Decodificação completa (endereço do passo: [w0 w1 (ptr)]):
| idx | início | passos |
|---|---|---|
| 0 | 99B | [CF 10] loop 9B (parado, flags C) |
| 1 | 99E | C0 12, C0 12, C0 14, C0 12, C0 12, C0 12, C0 14, C0 12, [C7 08] loop AE |
| 2 | 9B1 | C0 10, C1 FB(−6), F0 0C, C0 08, F2 07(+6), [C0 14] loop B1 |
| 3 | 9BE | C5 10, [C1 0E] loop BE |
| 4 | 9C3 | C0 10, C2 FD, F3 05, C1 FD, [F3 03] loop C3 |
| 5 | 9CE | C5 10, [D0 10] loop CE |
| 6 | 9D3 | C0 10, C3 FF, F7 03, [C2 FF] loop D3 |
| 7 | 9DC | C0 10, C2 FD, F5 05, [C1 FD] loop DC |
| 8 | 9E5 | C7 10, D3 10, [CB 10] loop E5 |
| 9 | 9EC | C7 10, [F7 10] loop EC |
