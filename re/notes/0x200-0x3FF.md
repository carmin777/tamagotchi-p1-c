# ROM 0x200–0x3FF — reset, tela do relógio, entrada de menu, despacho de eventos de cuidado

Fonte: `tools/asm.py 0x200 0x3FF` + rotinas chamadas (0x000–0x0FF, 0x5xx, 0x7xx, 0x8xx, 0xAxx, 0xCxx, 0xDxx, 0xFxx)
+ execuções do `harness/trace` (scripts em `out/r200/s*.txt`). `(?)` = hipótese.

## 0. Convenções necessárias para ler o código

- Rótulos `label_N` do agg23 não são endereços de página: `pset P; call X` chama `P:X`
  (ex.: `pset 0x5; call 0x4A6` = 0x5A6). Palavras 0x4xx/0x5xx no listing são a *codificação* de call/calz.
- `lbpx mx,0xHL`: grava **nibble baixo (L) em M(X)** e **alto (H) em M(X+1)**, X += 2. `retd 0xHL` idem (M(X)=L, M(X+1)=H). Logo `lbpx mx,0x3D` => M(x)=0xD, M(x+1)=3.
- `jpba`: PC = (NP<<8) | (B<<4) | A. `ld y,0xHL`: YH=H, YL=L. XP/YP = página (nibble alto) do endereço de RAM.
- Flags no registro F (usado por `push f; pop b`): C=bit0, Z=bit1, D=bit2 (decimal), I=bit3.
- **Botões** (tamalib `hw.c`): K00=R(C), K01=M(B), K02=L(A). Em RAM os bits são ativos-altos: bit0=R, bit1=M, bit2=L.
  - M(0x026) = botões *segurados* agora; M(0x027) = *bordas de descida* acumuladas (OR) desde a última leitura
    (também recebe repetição quando o mesmo estado persiste 8 ticks). Escritos pelo `prog_timer_int` (0x16F).
  - `copy_0x026_7_to_8_9` (0x021): A=M(0x026), B=M(0x027), zera 0x027, copia p/ M(0x028)=A, M(0x029)=B. **Retorna A=segurados, B=bordas.**
    Todo o código abaixo usa "A/B após esse call" e/ou testa M(0x028)/M(0x029).
- Pares de nibbles: valor de 8 bits = M(n) baixo, M(n+1) alto (little-endian de nibbles).
- Temporizador de espera: `copy_xhl_to_0x022_or_loop_0x023` (0x03C) põe XH:XL em M(0x022/023) e **bloqueia** até o `prog_timer_int` (256 Hz/divisor) decrementar até 0. `wait(n)` abaixo.

## 2. Rotinas

### 2.1 0x200–0x205 `poll_cancel_or_reset` (agg23 `label_70`)
Copia buffer→LCD, lê botões. `if (held==5) goto soft_reset` (L+R segurados). Retorno: **Z=0 se M(0x029)&1 (R pressionado)**, senão Z=1.
Chamadores: 0x3B0, 0x3C9 (tela de morte). Chama: copy_video_buf_to_vram, copy_0x026_7_to_8_9.
```c
bool poll_cancel_or_reset(void){ copy_video_buf_to_vram(); read_buttons(&A,&B);
  if (A==5) soft_reset(); return (B&1)!=0; }
```

### 2.2 0x206–0x226 `soft_reset_keep_clock` (`label_71`; L+R na tela de morte)
Reinicia o jogo preservando a hora: salva 0x010..0x015 em 0x272..0x277, SP=0xFF, flags=0, `set_init_mem_and_int` (apaga RAM e reinicializa I/O), restaura relógio, `set_f_0x07D`, música 0x80 (se 0x07B), `game_init` (label_232 @0x761: valores iniciais — 0x5D=0, 0x5E=1, 0x40=0x41=1, 0x46=5, 0x48..0x4F, 0x5C=0, 0x200..0x20F…, 0x0F=F, 0x12=F, 0x15=5, 0x16=0x28…), `render_pet` (label_142 @0x465), M(0x03C)=F, espera soltar todos os botões (`while(held&7)`), `goto pet_main_loop` (0x517).
Não retorna. Chamado só por 0x203.

### 2.3 0x227–0x229 `springboard_copy_6_mx_my` / `copy_6_mx_my_bank0_ret` — trampolim p/ página 0x12 (`copy_6_mx_my`, 6 nibbles MX→MY). 0x242–0x243 `springboard_set_init_mem_and_int` idem p/ 0x1E0.

### 2.4 0x22A–0x241 `reset_vect_cont` (cold start; vetor 0x100→0x114→aqui)
```c

M[0x270] = io[0xF40] & 7;                // K0 cru (ativo-baixo)
```

`set_init_mem_and_int_cont_mem_clear` 0x244–0x255 é a continuação (página 2) que limpa RAM com `clear_8_starting_at_a_xp` e salta p/ `..._cont_set_mem` (0x1200).

### 2.5 0x256–0x292 `factory_lcd_test` (`label_80/81/85/83/84`) — teste de LCD de fábrica (L apertado no reset)
Quatro padrões; cada um espera que **exatamente** um botão esteja segurado (A==M(0x000)), toca bipe (0x94) e segue.
| passo | máscara ícones 0x2C/2D | padrão do buffer 0x100–0x1FF (nibbles repetidos A,A,B,B) | espera |
|---|---|---|---|
| 1 | 0xFF | F,F,F,F (todos os pixels) | M (2) |
| 2 | 0x5A (2C=A,2D=5) | A,A,5,5 | R (1) |
| 3 | 0xA5 | 5,5,A,A | L (4) |
| 4 | 0x00 | 0x100–0x17F = (1,0)…; 0x180–0x1FF = (0,8)…; cantos 0x100,0x13E,0x180,0x1BE = FF (moldura) | M (2) |
Depois `goto 0x97F` (partida normal). Pseudo: `label_81(mask, pat, btn){ M[0]=btn; fill(0x100,256,A=hi(pat),A,B=lo(pat),B); update_icons(); copy_video_buf_to_vram(); do read_buttons(); while(A!=M[0]); tune(0x94); }`.

### 2.6 0x293–0x2C2 `clock_screen_loop` (agg23 `label_88/89/92/93`) — tela do RELÓGIO
Entradas: 0x2C2 (após evento), 0x4FD, 0x590 (saída do ajuste de hora). Loop:
```c
label_88: set_icon_mask(0) /*label_238*/; clear_page_0x100(); read_buttons();
label_89: cursor=(4,0xC); M[0x2A]=0,M[0x2B]=4;
  render_clock();                    // label_181 @0x5A6: limpa 0x2E; hh:mm (+AM/PM glyph A/B via m9 bit3 -> misc_render) no buffer
  /* barra de 5 células dos segundos: */ m5=5; a=M[4]; if(a>=6) a+=3; M[4]=a;
  for(i=0;i<5;i++){ M[4]--; glyph = 0xA | ((M[4]&8)?1:0); render_clock_with_b_0(glyph); }   // 0x2A4–0x2AC (?) m4 = nibble de segundos vindo de label_181
  copy_video_buf_to_vram();
  if (check_events()) { dispatch_event(); goto label_88; }     // 0xF00 -> NZ => 0x2C1
label_92:
  wait(2); read_buttons();           // store_0x02_into_0x022_3
  if (B&2) goto 0x508 /*M: vai p/ tela do bicho*/;
  if (A==5) goto 0x553 /*L+R: ajustar hora (set_time_mode)*/;
  if (M[0x7C]==0) goto 0x508 /*ovo pronto p/ chocar*/;
  if (M[0x2E]==0) goto label_92;     // espera 1 s
  goto label_89;                     // redesenha
```
Obs.: durante a espera de eventos esta tela também processa `check_events`.

### 2.7 0x2C3–0x2F2 `menu_poll_input` (`label_94`…`label_100`)  — **entrada do menu de ícones**
Chamadores: 0x530 (loop principal do bicho), 0xE65. Entrada: nada. Saída: A = M(0x075) (cursor); flags:
| situação | C | Z | observação |
|---|---|---|---|
| nenhum evento | 0 | 0 | |
| **L** (M(0x029)&4) | 0 | 0 | bipe(0x94); `if (++M[0x75] >= M[0x76]) M[0x75]=0` |
| **M** (&2) | 0 | 1 | bipe(0x94) — "confirmar" |
| **R** (&1) | 1 | 1 | bipe — "cancelar" |
| timeout (M[0x57]==0 && M[0x77]!=0) | 1 | 0 | |
Qualquer botão (`(A|B)&7`) recarrega `M[0x57]=M[0x77]` se 0x77≠0. O chamador faz `push f; pop b` e testa B&1 (cancelar/timeout → 0x517) e B&2 (confirmar → despacha pelo cursor via tabela 0x7xx).
```c
uint8_t menu_poll_input(flags *f){ read_buttons(); if((A|B)&7 && M[0x77]) M[0x57]=M[0x77];
 if(M[0x29]&4){beep(); if(++M[0x75]>=M[0x76]) M[0x75]=0; C=0;Z=0;}
 else if(M[0x29]&2){beep(); C=0;Z=1;}
 else if(M[0x29]&1){beep(); C=1;Z=1;}
 else if(M[0x57]!=0 || M[0x77]==0){C=0;Z=0;} else {C=1;Z=0;}
 return M[0x75]; }
```
0x2F3–0x2FF: 13×`nop7` (preenchimento).

### 2.8 0x300–0x306 tabela + 0x307–0x30B `dispatch_event` (`jump_table_0x300`)
```c
void dispatch_event(void){ ev = M[0x5C]; M[0x5C]=0; switch(ev){0:return;1:ev_bedtime();2:ev_call_a();3:ev_call_b();4:ev_idle_timer();5:ev_evolve();6:ev_death();} }
```
(`jpba` com B=0: PC=0x300+A; 0x300=`ret`.) Chamadores: 0x2C1 (tela relógio) e 0x54B (loop do bicho). Quem escreve 0x05C é `check_events` (0xF00–0xFD8, fora da faixa; retorna NZ se há evento) — resumo em §6.

### 2.9 Evento 1 — 0x30C–0x31B `ev_bedtime` (`label_102`) — hora de dormir
`M[0x4A]=0xF` (dormindo); `M[0x204..205] = (M[0x5D]==1) ? 0x3D : 0x00`; `jmp set_buzzer_0xA5` (0x318): `play_tune(ptr=0xA5, repeat=A=8)` = `xp_0_if_0x7B_set_clear_0x32_store_yhl` (se 0x07B≠0: M32=0, M36/37=Y, M58=A, M59=B=0).

### 2.10 Eventos 2 e 3 — 0x31C–0x328 (`label_106/107/108`) — chamadas de atenção
- Evento 2 (0x31C): `M[0x208] = (M[0x5D]==1) ? 0xD : 1;` depois `play_tune(0xA5,8)`.
- Evento 3 (0x324): `M[0x209] = 1;` depois idem.
Efeito colateral: 0x208/0x209≠0 ⇒ ícone "atenção" (0x2D|=8 em label_240/0x7D1). Eles sobem de 1 por minuto (0xCDB `label_328`, satura em F) até F ⇒ `check_events` conta erro de cuidado.
Trace: 1º evento 2 em t=310 s (logo após eclosão): 0x208 0→0xD, 365s E, 425s F (+0x42++), …

### 2.13 Evento 6 — 0x374–0x3CF `ev_death` (`label_116`…`121`)
Disparo (check_events 0xF74): `M[0x49]>=3` (3 doenças) **ou** inanição (não-bebê: 0x20A..C ≥ 0x2D0) **ou** doente por ≥ 0x160 min (0x20D..F) **ou** `M[0x4F]>=5`.

```c
do {                              // tela da lápide
```

## 3. Helpers de página 0 usados (para reescrita; 0x000–0x0FF)

## 4. Música: `play_tune(ptr, repeat)`
`xp_0_if_0x7B_set_clear_0x32_store_yhl(A=repeat)`: se M(0x07B)≠0: M(0x32)=0, M(0x36)=YL, M(0x37)=YH, M(0x58)=A, M(0x59)=B. ## 6. `check_events` (0xF00–0xFD8; fora da faixa, só o necessário)
Produz M(0x5C) e retorna Z=0 se ≠0. Só roda se M(0x7C)==F e M(0x5C)==0. Resumo (confiança média):
- dorme/acorda por horário (0x14/0x15 vs 0x31..0x34; bebê usa limiares diferentes): acordando faz M[0x4A]=0, M[0x4B]=F, idade 0x54/55++ (cap 99); hora de dormir ⇒ **evento 1**.
- 0x200/201 chegou a 0 (min): recarrega de 0x234/235; `M[0x40]` -= 4; se <4 ⇒ `M[0x40]=0`, **evento 2** (idem 0x202/203, 0x41, 0x236/237).
- 0x213/214 acumulador (≠bebê) estourou sem carry ⇒ **evento 3** (?).
- 0x206/207==0 ⇒ **evento 4**.
- 0x210..212==0: se M[0x50]<F ⇒ **evento 5**; senão M[0x4E]=F e `M[0x4F]++` (erro de vida útil).
- 0x20D..20F==0 e saudável ⇒ M[0x48]=F, M[0x49]++ (doente).
- morte ⇒ **evento 6** (condições em §2.13). Penalidades: `label_388`: M[0x42]++ (sat. F) e `M[0x4F]++` quando M[0x50]==F e 0x210..212==0; `label_389`: ++ saturado.
- 0x208/0x209==F ⇒ zera e erro (0x42++ / 0x51++).
Tick por minuto que alimenta tudo: `label_319` @0xCA1 (decrementa 0x200,0x202,0x206 (8 bits); incrementa 0x208,0x209 saturando; conta 0x20A.. se coração 0; 0x20D.. ±1; 0x210.. −1).

## 8. Dados: tabelas de evolução (`label_339`…`345`, 0xD9C–0xDC5; carregadas em RAM[0x90..] por `label_346`)
Entrada = 4 nibbles `[min_0x42, min_0x51, novo_0x50, novo_0x5D]`; vale a **primeira** entrada com `M[0x42]>=min0 && M[0x51]>=min1`.
